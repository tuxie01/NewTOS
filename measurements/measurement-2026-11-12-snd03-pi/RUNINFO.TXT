H4 -- boot state (page 1)
  At kernel entry (CNTPCT 2657319) and at the probe (CNTPCT 878798579) the same picture:
  SYST CS 00000000, C1 00000000, C3 00000000; C0 and C2 hold values near CLO (entry: CLO 00742806, C0 00742f13,
    C2 00745963). Within 100002 us: C0 016bd583 -> 016d5c23, C2 016bbc9a -> 016d47cf (the firmware re-arms C0 and C2);
    C1, C3 unchanged at 0. SYST CLO advanced 100003 in 100002 us: the system timer runs at 1 MHz.
  DMA ENABLE 00007fff (EN 7fff, PAGE 0, PAGELITE 0), INT_STATUS 00000000.
  DMA CS: ch 0,2,4,5,7,8,9,10 = 00000008; ch 1,3 = 20000008; ch 6 = 20000009; ch 11 = 20000309; ch 12,13 = 00000308;
    ch 14 = 20000308. CONBLK_AD 0 on all. DEBUG: 040180n0 for ch 0-6, 100187n0..10018a00 for ch 7-10, 1b000400..
    1e000400 for ch 11-14. "DMA channels with CS = CONBLK_AD = 0, no DEBUG error: mask 0000" (the probe's free test
    finds no channel because bit 3 is set on every CS; the mask is not usable as it stands).
  PACTL_CS 08800000 (bit 23: DREQ 1 = PWM1), set by the firmware.
  CM words at circle's PWM offset 0xa0/0xa4 (unsourced, read only): 00000200 00000000.
H3 -- DMA memory to memory, channel 5, 4096 bytes, PERMAP 0 (page 2); bus SRC c0200000 DST c01ff000 CB c01fe000
  run 1 (no cache maintenance): END after 125 us, CS 1000000e (END 1 INT 1 ERROR 0), INT_STATUS 00000020,
    TXFR_LEN 0. CPU reads DST: 0 new SRC, 0 old SRC, 1024 old DST (CPU sees its stale cached DST).
    After dc ivac DST (what the DMA wrote): 624 new SRC, 400 old SRC, 0 old DST (the DMA read SRC partly from RAM
    that the CPU's writes had not reached yet).
  run 2 (dc cvac SRC; dc civac + ivac DST): END after 132 us, CS 1000000e, DST 1024 of 1024 words = SRC.
  -> On the real Pi the CPU caches are not coherent with the DMA in either direction: clean before the DMA reads,
     invalidate before the CPU reads what the DMA wrote. With both, the copy is exact.

H1 -- clk_pwm
  Firmware view as found (mailbox, clock id 0x0a PWM): state 0 (off), rate 0, measured 65917968 Hz, max 500000000 Hz.
  PWM1 timing as found, RNG 10000: STA 00000101 (BERR 1), no FIFO word consumed in 200 ms: clk_pwm NOT running.
  Probe asked the firmware: Set clock state on -> reply 1; Set clock rate 100000000 -> reply 100000000.
  After the request: state 1, rate 100000000, measured 107143064 Hz, max 500000000.
  CM words at 0xa0/0xa4 (unsourced, read only): 00000096 00007800.
  Timing after the request, RNG 10000: STA 00000601 (no GAPO, RERR1, WERR1, BERR); 10716 words consumed in 27004279
    ticks (CNTFRQ 54000000), 10720 written => clk_pwm = 107143019 Hz (10714 periods/s per channel).
  -> The firmware accepts 100 MHz but the clock runs at 107.143 MHz (its own measurement and the FIFO timing agree to
     0.00004 %). Software must use the measured rate, not the requested one. Interpretation, unsourced: 107142857 Hz =
     750 MHz / 7, i.e. an integer divider on a 750 MHz source; not a fact until sourced.
