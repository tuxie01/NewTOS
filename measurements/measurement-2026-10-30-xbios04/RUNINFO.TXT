WHAT / WHY
  Before: Ikbdws (XBIOS 0x19) returned 0 and Bconout(4,c) returned 1, both silently: the bytes were
  dropped, no IKBD command took effect, no response packet came (audit probe W01-W04: EmuTOS calls
  statvec/clockvec/joyvec once each, NewTOS never;
  measurements/measurement-2026-10-28-xbios-chardev-audit/RUNINFO.TXT).
  Decision (TASK/XBIOS04 "Entscheidung"): no interpreter; the deviation goes into
  docs/COMPATIBILITY.md ("IKBD commands are not interpreted"), W01-W04 ACCEPTED; never silent
  (ADR-031): one warning per process for both calls together.
  Change: tos-api/src/bdos/process/hooks.rs gets a warning key after the hooks (IKBD_KEY,
  note_ikbd_ignored, Kind::IkbdIgnored) in the same per-process bit set and queue as the ADR-031 hook
  warnings; tos-api/src/xbios/system.rs ikbdws and tos-api/src/bios/chardev.rs IkbdPort::bconout
  call it. Answers unchanged (0 and 1). The kernel prints the queue after every trap as before:
    [hook] warning: slot <n> (PD 0x...) sent IKBD command bytes via Ikbdws|Bconout(4); IKBD commands
    ignored: NewTOS has no IKBD controller, so no mode changes and no response packets
    (TASK/XBIOS04, ADR-031)
