QUESTION
  Is there any wait (key, delay) between the end of a text-mode program started from the desktop and the desktop's
  redraw; how long does the text stay; what does the screen show afterwards. EmuTOS (oracle) vs NewTOS.

  Both sides: the text screen is cleared within one frame of the program's last output (EmuTOS <= 2 frames = 40 ms,
  NewTOS <= 5 ms); no key and no delay between Pterm and the redraw; the same sequence afterwards (white screen with
  hourglass, green desktop fill top-down, menu bar, window) ending pixel-identical to the screen before the launch.
  The control shows that a key wait is visible in this method: without a key the text screen stands (40 s / 59 s),
  RETURN releases it. EmuTOS call trace: after Pterm(0) only Setexc, Dsetdrv, Drvmap, Dsetpath, Setexc,
  Bconout ESC H ESC f ESC E, Mxalloc, Pexec(7)/Pexec(6) of the desktop, appl_init -- no console input call.
  NewTOS serial: Pterm'd -> "starting desktop NEWDESK" 0-25 ms later, no input call in between.
  Duration difference (2.9 s vs 0.3 s) = redraw speed (16 MHz 68030 emulated vs QEMU), not a wait on either side.
