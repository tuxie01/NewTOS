RESULT 1 -- H5 in QEMU raspi4b 11.1.2 (serial/qemu-h5.log, method/qemu-h5.sh; boot args serial=on sndprobe=qemu sndprobe=nowait)
  Kernel image: target/snd03-scratch/final/kernel8-snd-probe.img (gitignored), sha256
  0d8aed1d08032098a6605f57ce08f9db0abaa88deb80cd20294318a705049240 (rpi4 release, --features snd-probe).
  * The modelled DMA does memory to memory with PERMAP = 0: channel 5, TI 0x119 (INTEN|WAIT_RESP|DEST_INC|SRC_INC),
    4096 bytes, CB at bus 0xc01fe000, SRC 0xc0200000, DST 0xc01ff000 (bus = 0xC000_0000 | PA, datasheet 1.2.4).
    CS.END and CS.INT set after 109 us / 48 us (two runs), CS.ERROR 0, DEBUG 0; INT_STATUS 0x20 (= channel 5);
    after the run SOURCE_AD/DEST_AD = start + 0x1000, TXFR_LEN 0 (registers advance as the datasheet says).
    All 1024 words arrive in both runs (QEMU has no cache model, so "no maintenance" also gives 1024/1024: H3 needs the Pi).
  * The interrupt reaches the GIC distributor: GICD_ISPENDR bit of INTID 117 (= 96 + 16 + 5) reads 1 with the SPI disabled
    and enabled, and 0 after CS.INT was cleared (IRQs masked, no interrupt taken). Delivery through GICC_IAR to the CPU
    was not exercised.
  => A DMA driver can have QEMU tests for control-block execution, completion flags, the progress registers and the
     interrupt line at the GIC; the PWM side cannot (below).
  * QEMU firmware model, clock id PWM (10): Get clock state 1, Get clock rate 700000000, Get max clock rate 700000000,
    Get clock rate measured answers 0 bytes. Model values, not hardware facts. CPRMAN word at circle's offset 0xa0:
    0x00000200 (QEMU's cprman model; unsourced offset, read only).
  * H4 in QEMU: System Timer compare registers C0-C3 all 0, CS 0, CLO advances 1 per us (100101 in 100120 us of CNTPCT);
    DMA ENABLE 0x0000ffff, PAGE 0, all 15 channels CS = CONBLK_AD = 0.
  * Measured side facts on what QEMU does NOT model:
    - PWM1 (0xFE20C800): synchronous external abort, "ESR=0x0000000096000010 ... FAR=0xffff0000fe20c800"
      (serial/qemu-pwm-abort.log). Scratch build: kernel/src/snd_probe.rs with the one line `if qemu_mode() {` in `run`
      changed by hand to `if false && qemu_mode() {` for that build only and restored from a copy right after
      (no git command); image target/snd03-scratch/q-try3-pwm-scratch.img sha256
      7c2de99e059a327a952edb912f9b3fa25aca89d6a151df7e8ab269e74ba372de. This settles the open point of
      TASK/SND01.md section 1 ("RAZ/WI or abort"): abort.
    - PACTL_CS (0xFE204E00): without `sndprobe=qemu` the boot stops at the probe's first read of it, right after
      "Phase 02 reached." with no further output (serial/qemu-pactl-stop.log; earlier probe build, image
      target/snd03-scratch/q-try1.img sha256 8d5718bc79be585a35f3f4d7066760a4894fc4b6afdf3b6b816fa4172c3e60ef). No
      exception report because the exception vectors are not installed yet at that point (inference). Hence the
      `sndprobe=qemu` switch also leaves PACTL_CS out.
    - QEMU's DMA DEBUG register stored a blind W1C write of 7 and read it back as 7 (first run, not kept); the probe now
      writes DEBUG only when an error bit is set, and reads 0 in QEMU.
