WHY THE TEST IS SPLIT
  No QEMU board has USB and a drive: qemu-virt has the xHCI controller but no block device (no C:), raspi4b has the
  SD card but no USB ("[pcie] RC not present"). So:
    - qemu-virt: the measurement build method/usbsnap-virt.c (= sdk/examples/usbsnap.c unchanged + the two test seams
      of §9.1) runs as the embedded NEWDESK.NAP; real kernel answers; each file is printed to the console between
      FILE BEGIN/END markers (extract_files.py cuts them out) and every raw Ssystem(2022) answer is dumped as hex.
    - raspi4b: the product build USBSNAP.NCP for T7; for the file half the replay build method/usbsnap-replay.c,
      whose snap_call() answers with the raw kernel answers recorded on qemu-virt (serial/virt-capture.log ->
      mkreplay.py -> method/replay.h); it writes to a real FAT card, which fsck_msdos then checks.
    - MUTE as the AES sees it: probe method/mutechk.c (graf_mkstate + console queue) on qemu-virt.
  NOT reachable in QEMU: a click on the DESKTOP during the recording (the qemu-virt program replaces the desktop),
  double-click start from C:, the VL805 -- real-Pi test T8.
