MEASUREMENT ONLY. The format itself: docs/TOS-REFERENCE-DUMPER.md section 3

WHAT / WHY
  User decision 2026-10-26 ("option b, no CLI flag"): tosdump record format 3.
  The dumper writes its pointer width and word order into the header (bytes
  20..23, formerly reserved); nothing else in the record changes. tosdiff
  uses them for the field class "address": every address cell must be
  < 0x80000000 (a TOS address is a signed LONG, TASK/MEM11.md), reported as
  its own verdict; a format 2 dump reports the check as "not checkable";
  format 3 against format 2 is refused.
  This run re-records the pinned references tosdump/reference/EMUTOS-1a7484ab-*
  in format 3 on the pinned oracle and checks, per table, that the PAYLOAD
  (everything after the 32-byte header) is byte-identical to the format 2
  recording. No ticket carries this work; the run name was given by the lead.
  NewTOS-side dumps were NOT re-recorded (open user decision).

METHOD
------------------------------------------------------------------------------
  method/run-v3.sh <out-root>       14 Hatari sessions, one per table, one after
                                    another, via tools/hatari-oracle.sh (profile,
                                    table, build id per reference in the script)
  method/compare-v3.sh <out-root> <v2-dir>
                                    per table: sha256 of the payload of the
                                    format 2 reference and of the format 3 dump,
                                    equal yes/no (-> COMPARE.txt); both headers
                                    in hex, the LOG diff, and three tosdiff runs
                                    on the real data: v3 vs v3 (address check),
                                    v2 vs v3 (must refuse), v2 vs v2 (must say
                                    not checkable) (-> runs/<table>.detail.txt)
  <v2-dir> = copies of tosdump/reference/EMUTOS-1a7484ab-* taken from the clean
  tree at b63a5802 before anything was replaced.
  Control: tools/hatari-oracle.sh tt|falcontc dumpers-control-v2head/<id>/DUMPRAST.PRG
  on vdi-raster.tsv / vdi-raster-screen.tsv -> control-v2head/.
  runs/*/ keep <AREA>.BIN, <AREA>.LOG and hatari.log; the hd/ and home/
  directories were left in the scratch area.
