=============================================================================================

WHAT / WHY
  Until today every NewTOS tosdump run built its own script (dumper, card, QEMU, mcopy,
  tosdiff), and the auditor's pre-flight asked for a `cargo xtask` command that did not exist
  (TASK/TOOL09). The command is `cargo xtask tosdump`; this run is its acceptance: bios-r1 at
  the storage audit's commit reproduced in a tree other than the main tree, the disk round,
  the input check with bios-arg-trace, plus the copied-target guard, the time limit and a live
  crash screen.

THE COMMAND (tools/xtask/src/tosdump.rs, module doc = the full description)
  cargo xtask tosdump <dumper> <table.tsv> --out <dir> [--reference <BIN>]...
        [--tree <dir>] [--features a,b] [--disk | --testdisk <img>]
        [--scratch <dir>] [--time-limit <s>]
  - measured tree (--tree, default the xtask's own tree): `cargo xtask build --board rpi4
    --release [--features]` and tosdump/build-dump*-newtos.sh run IN that tree, with the
    outer cargo/rustup variables removed (its own rust-toolchain.toml and target/ apply).
    Its target/ must be its own: every artifact dep-info file (target/**/<artifact>.d) must
    name an artifact under that target/, checked before and after the build. A copied
    target/ (APFS clone of another tree) is refused with its own message.
    Why not a separate CARGO_TARGET_DIR: the build code of every commit up to this one
    hardcodes <tree>/target (xtask's kernel_elf_path/produce_kernel8_img,
    kernel/embed.rs programs_dir, programs/build.sh LIB) -- with the variable set, an older
    commit would fail to link or (in a copied tree) link stale programs.
  - instruments from the harness tree (the xtask's): tools/mkcard.sh, tools/mktestdisk.sh,
    tosdump/host tosdiff (make build/tosdiff), tools/biostrace-check.py.
  - card in <scratch>/tosdump-<pid>/ with NEWDESK.INF "#R 02" + "#Z 01 <d>:\DUMP*.NAP@"
    (byte-equal to the audits' z-dumpbios.inf / TOOL07's newdesk-d.inf, host test), booted as
    an APFS clone (cp -c); QEMU raspi4b -no-reboot -display none -append serial=on.
  - end: "desktop up" after the dumper (+3 s as the scripts), or with its own message on
    [PANIC] / [EXC] / [crash] slot (crash screen), the desktop without the dumper, QEMU exit,
    or the time limit (default 480 s); QEMU is killed in every case.
  - --out (new or empty): BOOT-SERIAL.txt, <AREA>.BIN/.LOG, card.img.manifest (+
    test.img.manifest), the dumper, kernel-build.log, dumper-build.log, mkcard.log,
    tosdiff-validate.txt, tosdiff-<reference>.txt per reference, cmp/, testpart-compare.txt
    (disk), biostrace-check.txt (bios-arg-trace), tosdump-run.txt (commit, dirty paths,
    kernel8.img and ELF sha256, dumper build id and sha256, table sha256, manifest
    image_sha256 and optional_missing lines verbatim, card sha256 before and after the run,
    every result line). Scratch subdirectory deleted at the end, also on failure.
  - exit 0 = run complete (tosdiff/checker differences are findings); non-zero = a step
    failed, the run ended abnormally, the dumper's rc != 0, a dump was refused.

METHOD (method/)
  runs.sh <scratch>        runs 1-3 (the three calls and the clone of run 3)
  crash-demo.sh <scratch>  run 6 (builds the crashing probe, one call)
  run 4 and 5 were single calls from the main tree:
    cp -c -R <scratch>/tree-c3db <scratch>/tree-c3db-copy      (after run 3)
    cargo xtask tosdump bios tosdump/cases/bios-r1.tsv --tree <scratch>/tree-c3db-copy \
        --out <scratch>/guard-out --scratch <scratch>           -> runs/guard-copied-target/
    cargo xtask tosdump bios tosdump/cases/bios-r1.tsv --out runs/timelimit-head \
        --time-limit 5 --scratch <scratch>
  <scratch> = the session scratchpad .../scratchpad/tool09 ($CLAUDE_JOB_DIR was unset).

LIMITS
  - QEMU raspi4b only (the command boots no other board).
  - The dumper's own output files are the only files collected (a probe's own LOG, as in
    run 6, is not).
  - --tree with a pre-TOOL09 commit works (run 3) because only the harness tree runs this
    command; the measured tree is built with its own `cargo xtask build`.
