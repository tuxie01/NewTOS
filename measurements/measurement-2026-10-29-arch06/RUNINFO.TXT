RESULT 1 -- _MCH reads back as 0xFFFFFFFF in every form
  a) Kernel cookie selftest (runs/st-mch/serial.log, kernel8-st.img): "[cookie] === Cookie jar PASS (18/18) ===", including
       Getcookie(_MCH) value form = -1 (0xFFFFFFFF): OK
       Getcookie(_MCH, &v) = E_OK, v = 0xFFFFFFFF: OK
       _MCH: value form x0 = 0xffffffffffffffff, pointer form rc = 0, v = 0xffffffff
     (an EL1 svc #1 caller; the pointer is a kernel address, Space::Kernel)
  b) EL0 program, C:\AUTO\MCHPROBE.NCP (runs/st-mch/MCHPROBE.LOG; identical lines in every run):
       V _MCH Ssystem(S_GETCOOKIE, 0x5F4D4348, 0) x0 = 0xFFFFFFFFFFFFFFFF (-1)
       P _MCH Ssystem(S_GETCOOKIE, 0x5F4D4348, &v) rc = 0, v = 0x5A5A5A5AFFFFFFFF
       G _MCH Getcookie(0x5F4D4348, &v) rc = 0 (C_FOUND), v = 0x00000000FFFFFFFF
       V ZZZZ Ssystem(S_GETCOOKIE, 0x5A5A5A5A, 0) x0 = 0xFFFFFFFFFFFFFFFF (-1)
       P ZZZZ Ssystem(S_GETCOOKIE, 0x5A5A5A5A, &v) rc = -1, v = 0x5A5A5A5A5A5A5A5A
       G ZZZZ Getcookie(0x5A5A5A5A, &v) rc = -1 (C_NOTFOUND), v = 0x0000000000000000
       J   slot  1 tag 0x5F4D4348 _MCH value 0xFFFFFFFF          ($5A0 mirror, Setexc(0x5A0/4, -1) = 0x5F0)
     - value form: _MCH and an absent tag both give x0 = -1 (sign-extended); only the pointer form tells them apart.
     - pointer form: the kernel writes 4 bytes; the upper half of an 8-byte long keeps what was there (sentinel 0x5A5A5A5A).
       mintlib Getcookie presets long v = 0, so a program sees 0x00000000FFFFFFFF (zero-extended), as the ADR-012
       amendment states.
  c) mintlib after SDK03: S sysinfo(SI_PLATFORM) = 8 "unknown"; sysinfo(SI_HW_PROVIDER) = 8 "unknown";
     uname() = 0 machine "unknown" sysname "TOS" -- no NULL dereference.
  d) zView (sdk/zview/overlay/zview/plugins/jpg/jpgldg.c:801-813): the `mach == 0x50000L` branch runs only when _JPD exists;
     the jar has NTOS _MCH _IDT _AKP EdDI only (J lines), so it stays dead. Not run (code reading).
