2. READ end_unused_grant (tos-api/src/aes/window.rs:4237-4258, crysbind mod.rs:885-889) against EmuTOS (aes/gemflag.c:105-130, gemwmlib.c:1415-1422,
   1443-1450, 1632-1638, 1879-1883 wm_new):
  - Release of a lock the caller legitimately holds (nested BEG_UPDATE by itself)? No: the function does nothing unless UPDATE_GRANTED[me] is set
    (swap -> false). The flag is only set by unsync's hand-over (lock becomes (1, me)) and by wm_new's drain (lock 0, no count). A caller that
    holds the lock itself and makes a refused window call has no flag -> returns at the first line (every_taker_nests_.. and
    r_grant_flag_is_reset_.. exercise refused calls inside the caller's own hold: lock unchanged).
  - Double release? The swap clears the flag before the unsync; a parked call is re-executed once per hand-over; the second call finds no flag.
    (mutations g/q show the tests see a flag that is not cleared / a second unsync.)
  - wm_new drain: the drain grants without a count and leaves the lock 0/NO_OWNER, so the guard UPDATE_LOCK>0 && same_holder is false -> the grant is only collected.
    If C takes the lock in between, same_holder(C, B) is false -> C's lock untouched (r_drain_.. proves it; j shows the test needed it).
    Residual theoretical case, no test, not seen: drain grant to B, then ANOTHER IDENTITY OF B'S OWN application chain (same_pd fold) takes the lock, then
    B's call refuses -> same_holder true -> that identity's lock is released. Requires two identities of one chain racing in the window between the
    drain and B's re-execution.
  - Gate/else structure: end_unused_grant sits in the `else if matches!(101|102|103|105)` of the gate, i.e. only when opcode_takes_lock is false
    for this call; with gate true the grant is collected by tak_flag in update_beg as before (mutations h/i differ only in order/exclusion, see above).
  - EmuTOS difference (named in the spec "A refusal after the wait"): EmuTOS would continue with the body on the window it validated BEFORE the wait; here the
    re-executed call returns the refusal the table gives now. Lock outcome identical. I agree with the spec.
