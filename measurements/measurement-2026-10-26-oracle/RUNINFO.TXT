METHOD
------------------------------------------------------------------------------
  method/run-set.sh <rom> <tag>   14 Hatari sessions, one per EMUTOS14-* table,
                                  via tools/hatari-oracle.sh (profile, table and
                                  build id per reference are listed in the script)
  method/compare-set.sh <tag> <against>
                                  cmp BIN, cmp LOG, tosdiff per reference;
                                  writes runs/<tag>/COMPARE-vs-<against>.txt
  The sessions run one after another. Each ends when the dumper's final LOG is
  on the drive (Hatari SIGKILLed). runs/*/<ref>/hd/ (dumper + table copies) was
  deleted after the runs; tables are tosdump/cases/*.tsv at f2fae9f0.

  Comparisons use tosdiff with field class "address" for ap_3resv
  (global[11..12]) -- introduced in this work unit after step 1, approved by
  the user 2026-10-26; it changes the comparator only, not a recorded byte.

NOTES
------------------------------------------------------------------------------
  * *.BIN here is ignored by the root .gitignore (core.ignorecase); the pin
    set and the canary dumps are committed with `git add -f`, the release
    and own-1.4 dumps are not (sha256 in manifest.sha256 covers all).
  * The first control run was killed and redone: hatari-oracle.sh then
    stopped Hatari with SIGTERM (quit dialog on the user's screen) and took a
    LOG ending in "running N cases" (written before the first case) as done
    (EMUTOS14-AES-r3 had no dump). Both fixed before the runs listed above.
  * No Hatari process left behind (pgrep after each set: empty).
  * Hatari --saveconfig writes into the --configfile path: it overwrote
    tools/oracle/hatari.cfg once during the config comparison; the file was
    rewritten and all comparisons were then made on scratch copies.
  * tools/emutos-config.sh (separate commit): CONF table byte-identical
    before/after switching it to oracle.env. Found on the way, not fixed:
    its row order depends on the locale (env -i / C locale moves
    CONF_WITH_TTRAM and CONF_WITH_ST_MMU); the committed table was made
    under de_DE.UTF-8.
  * Nothing flashed, no card touched.
