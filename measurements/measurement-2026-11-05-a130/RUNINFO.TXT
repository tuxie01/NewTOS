  A press in the WORK area selects a configuration by column (x 120 = size 1000, 220 = 300, 310 = -1 the

  position +-250 (page) / +-50 (line), clamped 1..1000, wind_set. Every message is logged with its 8 words;
  a run of equal WM_ARROWED is logged as one R line plus one X line with the count.

CAUSE (code read after the measurement, localization)
  NewTOS tos-api/src/aes/window.rs drag_elevator (:5516): a loop that calls draw_vslider/draw_hslider
  (track G_BOX with its 0x1111 pattern, then the elevator on top, :5550-5560) on EVERY pass, then
  host.pump_input() (:5567), which is one non-blocking pass (kernel/src/host_env.rs:91 pump_input, no
  wait) -- so the track pattern is repainted and covered again continuously while the button is held,
  moving or not; any reader of the framebuffer (HDMI scan-out, QEMU's display update) catches the pattern
  between the two fills. Its value: travel = track_len - thumb_len, mul_div_round(rel, 1000, travel)
  (:5523, :5541), 0 when travel = 0. EmuTOS aes/gemctrl.c:295-306: ob_change(elevator, SELECTED), then
  gr_slidebox (aes/gemgrlib.c:358-413) -> gr_dragbox (:241-267) -> gr_wait (:169-191): XOR outline drawn
  once, wait for a mouse change (gr_stilldn), erase, redraw -- nothing is repainted while the pointer
  stands still; the value uses the 3D-grown outline (divis = c.g_h - t.g_h, the ADJ3DSTD correction).
  Page: EmuTOS gemctrl.c:262-285 + handle_arrow_msg :111-139 (send while held); NewTOS hctl_window arrow
  arm (:5897-5935): one WM_ARROWED after wait_release. Hit test: EmuTOS ob_find via ob_actxywh
  (gemoblib.c:1049-1080, :313-335: an FL3D object answers for its grown rect); NewTOS gadget_at
  (window.rs:5144, :5166) tests the un-grown elevator rect.
