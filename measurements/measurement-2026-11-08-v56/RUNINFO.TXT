1 CAUSE (evidence/)
  llvm-nm -C, base release ELF: tos_api::vdi::mouse::mov_cur and ::just_rts at ONE address 0xffff00000010cff8 (both
  ".llvm.<hash>" local), no aes_wheel_token symbol (evidence/llvm-nm-base.txt). vex_wheelv (evidence/vex_wheelv-base.dis):
  one "cmp x10, x21" with x21 = adr just_rts, then cbz, then slot_for; the kind is "csel w8, #2 / wzr" -- the constant 1
  (WHEEL_KIND_AES) does not occur: the `new == aes_wheel_va()` branch was folded away with the token.
  Which pass: method/nomerge.sh builds the same base tree once more with `-Z merge-functions=disabled` (other flag as
  .cargo/config.toml): aes_wheel_token 0xffff00000010d848, mov_cur ...dbb0, just_rts ...dbc0 -- three addresses
  (evidence/llvm-nm-base-nomerge.txt). So LLVM's MergeFunctions pass (on by default in rustc) folds them, no linker ICF
  (none is enabled for this target). LLVM IR of tos-api (host, release): the three markers are
  `define internal void ... unnamed_addr` (evidence/ir-base-markers.txt) -- rustc declares every function's address
  insignificant, which is what licenses the fold.
