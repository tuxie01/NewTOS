WHAT THE LOGS SHOW
  Every wireless receiver offers the boot mouse -- on interface 1, behind a boot keyboard on interface 0:
    046d:c52b Logitech Unifying  iface 0 boot kbd ep 0x81 | iface 1 boot MOUSE ep 0x82 | iface 2 report-only
    1997:2433 Rii X8             iface 0 boot kbd ep 0x81 | iface 1 boot MOUSE ep 0x82 | iface 2 boot kbd
    046a:0115 Cherry DW 9000     iface 0 boot kbd ep 0x81 | iface 1 boot MOUSE ep 0x82 | iface 2 report-only
  The driver configures iface 0 as a keyboard and skips iface 1 with "second HID boot interface: one
  interface per device" (F2 rule). The mouse of these receivers is therefore never polled. Cause of the
  dead mouse = one interface per device (USB01 F3), NOT a missing report parser.
  All EP0 transfers Success, 9-12 xHCI commands, no limit hit, no stray event, in all 11 logs.

  Open, not explained by these logs:
  - "Tastatur nein" in starts 1/2/5-8: the cable Cherry keyboard (slot 3) is configured exactly as in the
    working starts 3/4; the only difference is a second configured keyboard (the receiver's iface 0, slot 2).
    The logs stop before any input, so they cannot show what happened. Candidate to check, not proven: the
    boot-keyboard diff state is one global for all keyboards (kernel/src/drivers/usb/hid.rs:47 PREV).
    A USBSNAP recording with a receiver plugged in would show both keyboards' report streams.
  - "Zeiger ja" with a mouse interface that is never polled: probably means "pointer visible", to ask.
  Gamepads: 8BitDo reports as 045e:028e (Xbox 360 / XInput, class 255, no HID) -- not a HID device.
  basetech_joypad.LOG lists only the keyboard and the B100: the gamepad does not appear at all in it.
  Apple keyboard hub 05ac:1003 + B100 behind it: mouse + keyboard configured, as in our own MAUS3 run.
