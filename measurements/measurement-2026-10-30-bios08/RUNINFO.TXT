measurement-2026-10-30-bios08 -- BIOS handles 6 and up go through the one-entry Bconmap table
like EmuTOS (TASK/BIOS08, audit finding BIOS-CORE-007): handle 6 = entry 0 = AUX, 7 and up 0
=====================================================================================================
Developer, TASK/BIOS08, 2026-10-30 (host clock CET). Tree: main at 60824ec8 (later 57549ee4, see
KERNELS) plus the uncommitted BIOS08 change (TASK/BIOS08-STATUS-DONE.MD lists the files). QEMU
raspi4b headless, -append serial=on. No hardware, no real card, nothing flashed. Not committed.

WHAT / WHY
  Before: BIOS handles 6/7 were the absent device of the NewTOS device table and 8/9 lay past it
  (tos-api/src/bios/chardev.rs DEVICES, NDEV 8): Bconstat/Bconin/Bcostat/Bconout all 0. EmuTOS
  runs the BCONMAP_AVAILABLE branch first in all four calls (references/emutos/bios/bios.c:923-928,
  :967-972, :1000-1005, :1152-1157): map_index = handle - 6 in a WORD, >= maptabsize -> 0, >= 0 ->
  maptab[map_index]'s routine. Since XBIOS05 NewTOS has EmuTOS' one-entry table (maptabsize 1,
  entry 0 = the MFP/AUX port, references/emutos/bios/serport.c:962-972). Profile (ticket, lead
  2026-10-30): handle 6 = maptab[0] = AUX, the same answers as handle 1 (Bconin(6) waits like
  Bconin(1)); handles 7, 8, 9 and up 0.
  Change: chardev::device(handle) routes like EmuTOS (Bconmap branch, then table 0..5, negative 0);
  xbios::bconmap::entry_device gives entry 0's port = device 1 (AUX); the table ends at 5.
