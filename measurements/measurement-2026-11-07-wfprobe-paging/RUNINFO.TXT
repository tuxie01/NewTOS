WAITS AND THE FAULT
  arm() sets "hold": from there to the end of the program the pager never waits. Reason: disarm() does not end a
  fault's busy or programming time (kernel/src/drivers/bcm2711/emmc_fault.rs:86@arm stores no BUSY_UNTIL/PRG_UNTIL;
  busy_until/prg_until run on), so R1..R4 after disarm, and the log write, still depend on the time since the fault
  (cases u4/u5/p2 in the HW08 acceptance). Page breaks can fall only before arm(): menu, case header, layout,
  BASE.DAT save, "diag after the baseline" (nothing armed, nothing pending); at 640x480 and 1920x1080 the first
  page does not fill there for the interactive cases. If the screen ran full while holding, the run is shown once
  more after the log is closed, paged, from the top of the page that was open at arm() (marker line
  "--- the run once more, paged (no waits while a fault can be pending)").

  Rejected first version (rejected-hold/): held lines were NOT drawn during the run and paged out afterwards.
  Measured: that changes the measurement. R1 then came ~100 ms earlier after the 1200 ms busy fault, the driver
  waited dat_inhibit 98.1 ms and one write fell into the <250 ms bucket; with the lines drawn as before
  (interactive-before/, paging/) dat_inhibit 0.0 (compare.txt, last part). So the final version prints every line
  inline exactly as before (same Cconws calls) and only re-shows afterwards.
