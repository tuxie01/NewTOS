    NEWDESK.INF = method/z-qed.inf (`#R 02`, `#Z 01 C:\Apps\QED\QED.NAP@`). Booted as an APFS clone.
    The AUTO probe runs before the AES, prints to the console (mirrored on the serial log) and writes
    C:\CKPROBE.LOG, read back from the clone with mtools; then the AES autoruns QED.
  QED's _idt: QED keeps the cookie value in `static long _idt` (sdk/apps/qed/src/global.c, set in
    init_global from getcookie("_IDT"), 0x112E when not found). No QED source was changed. After 45 s
    (QED's menu bar is up, runs/*/qed.png) the HMP monitor (pipe chardev, no socket) takes a
    screendump and `pmemsave 0 0x40000000` (1 GiB of RAM). method/find-idt.py locates QED's TPA in the
    dump -- the first 256 bytes of QED.NAP's executable PT_LOAD searched in RAM, a hit accepted only if
    the BASEPAGE at B = hit - p_vaddr has p_lowtpa == B (NewTOS maps the TPA VA = PA) -- and reads the
    8-byte long at B + the llvm-nm offset of `_idt` (0x6e270 in both QED.NAP).
    Each side: 3 hits, exactly one a TPA (B = 0x1a07000); the other two are a copy of the text at
    0x2da000 (p_lowtpa 0x7) and the whole file at 0x399c8c00 (p_lowtpa = "\x7fELF"), both rejected.
  HMP note: pmemsave's size is parsed as an expression, so an absolute file name after it reads as a
    division ("invalid char 'p' in expression"); QEMU therefore runs in the scratch dir and gets
    relative file names.
