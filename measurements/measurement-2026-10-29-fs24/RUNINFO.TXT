  THE RESIDUUM (why the fix was stopped). The "option B" column is derived from NewTOS' code, not
  measured (no prototype was built, per the user's order):
  - V2, case 117: NewTOS' Fsfirst(C:\NEWDESK.INF) reads the root's first sector through the data list of
    the sector cache (tos-api/src/bdos/fs/find.rs:263@scan -> Volume::read_rel_sector -> cache::read);
    the arming preludes are BIOS Rwabs calls of sector 0 and touch no BDOS cache slot (the only
    invalidation is the re-login, tos-api/src/gemdos/mod.rs:254@media_change_relog). The peek would find
    SUB in that cached sector, Dsetpath would not meet the change, Mediach would stay 2 -- the oracle
    says 0. A case that is EQUAL today would newly differ. (Researcher's residuum (ii).)
  - V3, case 149: the data list has 8 slots (tos-api/src/bdos/fs/cache.rs:56@SLOTS). After the listing
    read the root sector, Fcreate reads C:\SUB's directory sector and the ten Fwrites bring ten partial
    file sectors through the data list (tos-api/src/bdos/fs/fsio.rs:168@partial: 100 bytes into record
    0, then each 1024-byte write a partial head, one whole record bypassing the cache, a partial tail
    in a new record) -- eleven newer sectors, so the root sector is evicted. The peek would miss, fall
    back, meet the change: Mediach 0 -- the oracle says 2. The case stays different. (Residuum (i).)
  Option B therefore cannot make V2 and V3 EQUAL: the sector cache is not a stand-in for "folder logged".

FINDING N1 (outside the ticket; not fixed) -- cases 87, 118, 150
  Dsetpath that met the change and restarted returns E_OK, but Dgetpath afterwards reads the root (""),
  the oracle "\SUB". Derived from the code (Schluss, the symptom is measured): after a re-login
  curdir::free_drive (tos-api/src/bdos/fs/curdir.rs:332@free_drive) frees the drive's dirtbl slots but
  leaves the PD's p_curdir byte naming the old slot. The restarted Dsetpath's set_curdir
  (tos-api/src/bdos/fs/curdir.rs:225@set_curdir) first takes a slot for "\SUB" -- incr picks the first
  free slot, the same index the stale byte names -- and only then reads the old byte; live(old) is now
  true, so decr frees the slot just taken, and the directory reads as the root. In S03 (case 77 EQUAL)
  the byte was 0 before. EmuTOS reads olddir before findit (bdos/fsdir.c:1129, 1134), and ckdrv repairs a
  stale byte to a fresh root slot first (bdos/fsdrive.c:121-130), so its decrement hits that root slot.
  Independent of option B: with B, V1a (no cached sector) and V3 (sector evicted) still restart.
