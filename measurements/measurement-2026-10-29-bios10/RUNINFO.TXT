THE PROBE (tosdump/probes/ksprobe.c, header comment = full description)
  Part K: K01-K13 = the audit probe's Kbshift lines (bcprobe.c group_k), same calls and format.
  Part H: conterm |= 8, &= ~2 (shift byte in Bconin, no key repeat); KSPROBE.RDY; then a poll
  about every 5 ms (busy loop calibrated against _hz_200; timing decisions read _hz_200):
  Bconstat(2), Bconin(2) when a key is queued (keeps the queue empty: NewTOS pumps the input in
  Bconstat only then, kernel/src/host_env.rs fill_from_device), Kbshift(-1); each change = a T line.
  Key sequences A-E (ksprobe-keys.txt), 1 s quiet -> Kbshift(0x80) (H01/H02), sequence F, 1 s quiet
  -> restore (H03), Q/A lines = the keys read (shift byte + scancode / ASCII), H04 their count.
  I00 = the calibration, side-specific, not compared.
  Keys: EmuTOS through Hatari --cmd-fifo "hatari-event keydown|keyup <scancode>", 0.3 s after
  C:\KSPROBE.RDY, the tick gaps as wall-clock pauses (runs/ksprobe-EMUTOS-*/inject.txt); NewTOS
  through the injector at the same ticks after the launch (BOOT-SERIAL.txt "[inj] ... feed").
  A development version polled only Bconstat + Kbshift without reading the keys: on NewTOS the
  shift byte then froze after the first queued key (see OBSERVATIONS); development runs stayed in
  scratch and are not evidence.

OBSERVATIONS (findings outside BIOS10, reported, not fixed)
  O1 No keyboard mouse emulation on NewTOS (handle_mouse_mode unmapped in mapping.tsv): Alt+Clr/Home
     and Alt+Insert are queued as keys; EmuTOS turns them into right/left mouse buttons. Q lines.
  O2 NewTOS' AES key state (graf_mkstate, EV_KS) returns the whole byte; EmuTOS' AES reads
     vq_key_s = Kbshift(-1) & 0x0f (aes/gemgsxif.c:432-436, vdi/vdi_input.c:185-188). CapsLock
     leaked before BIOS10; bits 5-7 can now too. Not measured (code reading).
  O3 The shift byte follows NewTOS' trap-side input pump: Kbshift does not pump, and Bconstat(2)
     pumps only while the key queue is empty. A program polling Kbshift(-1) with a key queued (or
     with no pumping call at all) sees a stale byte; EmuTOS updates shifty in the interrupt.
     Seen in the development run (section METHOD), from code kernel/src/host_env.rs fill_from_device.
