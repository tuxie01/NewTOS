  FINDINGS (NewTOS vs EmuTOS, both profiles unless said) -- for triage, not fixed:
   F1 Setexc(2,-1), Setexc(0x21,-1) [cases 53, 54]: NewTOS 0, EmuTOS a ROM vector; NONZERO
      fails. (0x100/0x101/0x102 agree.)
   F2 Bcostat(3), (4), (6), (7) [66, 67, 69, 70]: EmuTOS -1 (IKBD/MIDI ready, Bconmap
      devices), NewTOS 0.
   F3 Setcolor(0,-1), (1,-1) [93, 94]: EmuTOS 0x0FFF / 0x0F00 on both profiles, NewTOS 0 --
      the ST palette shadow does not hold the boot palette.
   F4 Iorec [98-102]: unimplemented on NewTOS (returns 0x0E): PTR_RAM fails for devices
      0-2, and the invalid devices answer 14 instead of -1.
   F5 Rsconf(-1 x6) [105]: the packed ucr/rsr/tsr differ -- EmuTOS tt 0x88018100,
      falcontc 0x88000000, NewTOS 0x88010100 -- AND NewTOS returns the ULONG zero-extended
      (0x0000000088010100) although tos_api::trap documents x0 as the sign-extended TOS
      LONG; EmuTOS's d0 reads as 0xFFFFFFFF88...... in the 64-bit comparison.
   F6 Giaccess(0,7), (0,14) [128, 129]: NewTOS 0 (documented PSG adapter), EmuTOS 0xC0 and
      0xA7 (tt) / 0x27 (falcontc).
   F7 Floprate(0,-1), (0,-4) [178, 179]: NewTOS EUNDEV (documented floppy adapter), EmuTOS
      3 / -1 (drive A present on the oracle).
   F8 Bconmap(-1), (-2), (0), (10) [183-186]: NewTOS 0x2C for all (documented "single
      serial port"), EmuTOS 6/7, a pointer, 0, 0.
   F9 NVMaccess [189-194]: unimplemented on NewTOS (0x2E, nothing written); EmuTOS reads
      48 bytes / answers -5 on both profiles.
   F10 Vfixmode(0x1C) [215]: EmuTOS -32 (tt) / a mode (falcontc), NewTOS 0x5F.
   F11 Dsp_Available [219, 220]: EmuTOS writes both LONGs even without a DSP
      (bios/dsp.c:619 has no has_dsp test), NewTOS writes nothing.
   F12 DMA sound inquiries [230-235]: EmuTOS answers on both profiles (TT DMA sound /
      Falcon codec), NewTOS returns the function numbers; Buffptr writes nothing.
   Profile-only (NewTOS matches one EmuTOS profile):
   P1 TT shifter [200-208]: NewTOS returns the numbers, like EmuTOS on the Falcon.
   P2 Getrez [87]: NewTOS 4 like the TT; falcontc answers 2.
   P3 Videl [211-214] and DSP inquiries [218, 221-227]: NewTOS returns the numbers like
      EmuTOS on the TT; falcontc answers.
   Rule question, reference side:
   R1 PTR_RAM's "multiple of 4" fails on the REFERENCE itself: Iorec(2) 0x30E2,
      Keytbl 0x40AE, Bconmap(-2) 0x4A76 (both profiles) and Iorec(0) 0x478A (falcontc):
      m68k structures are WORD aligned. Open question for the lead -- the rule
      (docs/TOS-REFERENCE-DUMPER.md section 6) was implemented as written and not changed
      after seeing the data.
