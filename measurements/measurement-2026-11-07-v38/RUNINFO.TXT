WHERE THE BRAKE SITS
  tos-api/src/vdi/contour.rs: Flood::run (EmuTOS contourfill main loop, vdi_fill.c:1003-1062) checks a span
  budget after the "queue empty" exit and before the next entry is taken; budget = BRAKE_SPANS_PER_PIXEL (16) x
  screen width x screen height (Flood::new). A fill that empties its queue within the budget runs exactly as
  before; at the budget the fill returns like a finished one (Stop::Brake, ignored like Stop::Overflow: no
  error channel), what is drawn stays drawn. Each pass between two takes is bounded (end_pts by the clip width,
  the queue scans by QSIZE = 1024, the take scan terminates because queue[qtop-1] is never EMPTY), so the main
  loop is the only unbounded one and the take count bounds the whole fill.

INTERRUPTS (read)
  Exception entry sets PSTATE.{D,A,I,F} (ARM ARM DDI 0487M.c D1.4.2, rule R_WTXBY; docs/MEMORY.md:3690).
  The SVC path: EXC_BODY (kernel/src/arch/aarch64/exception_vectors.s:23@EXC_BODY) saves the frame and calls
  rust_sync_handler without touching DAIF; TrapClass::Gem selector 115 calls tos_api::vdi::dispatch_in
  (kernel/src/arch/aarch64/exceptions.rs:531@dispatch_in); screen() dispatches 103 to
  contour::v_contourfill (tos-api/src/vdi/mod.rs:554@v_contourfill). The only places that unmask IRQs inside
  a trap are the wait loops (kernel/src/host_env.rs pump_input, console_read_byte_blocking,
  console_read_key_blocking, read_key_loop; kernel/src/console.rs aux_read_blocking); v_contourfill calls
  none of them, only the raster backend (get_device_pixel_wrapped, device_to_rgb565, read_pixel,
  fill_pattern). So a fill that never ends runs with IRQs masked: no timer tick, no USB, the machine stops.
  The ticket's claim holds.
