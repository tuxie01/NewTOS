WHAT / WHY
  Iorec returns a pointer to an IOREC, Getmpb fills an MPB whose first field points at an MD:
  the structure is the result. A call table could only copy raw bytes behind a returned
  pointer (r:<len>, TOOL07) and check the address (PTR_RAM, TOOL11); it could not say that the
  m68k and the LP64 structure lay their fields at different offsets, nor follow a pointer
  field, nor write a field. The acceptance of XBIOS01 and BIOS06 hangs on that (BIOS13 point
  7). TOOL16 adds: layouts (field, type, both ABIs' offsets, the compare class) from
  docs/api/, a capture through a layout, a follow rule with its own error value, tosdiff
  field by field, and -- the user's addendum -- one write through the returned pointer
  ("+put"), first user the XBIOS01 flush ibufhd = ibuftl, then Bconstat(2).

DESIGN (docs/TOS-REFERENCE-DUMPER.md section 6, "Structures behind a pointer")
  Source of the layout: a ```tosdump-layout block in the structure's spec,
  docs/api/structures/iorec.md (iorec, extiorec) and docs/api/structures/md.md (md, mpb), one
  "!layout <name> <m68k>/<LP64> <fields>" line each; a field is
  <name>:<type>@<m68k off>/<LP64 off>[:<class>], types b w L l p p><layout> [<layout>].
  The case table carries a byte-identical copy (it is the one file carried to both machines,
  its CRC the dump's identity); the host test layoutcheck (tosdump/host/layoutcheck.c, in
  make -C tosdump host-test) refuses a table line that is not a spec line and a spec block
  that does not parse. The loader (td_layout_parse) checks every offset and size against C on
  both ABIs (m68k: everything but a UBYTE WORD aligned; LP64 natural; no gaps; size = end
  rounded to the alignment); layouts name only earlier layouts (no loops), at most 2 pointer
  hops, 8 layouts, 32 slots.
  Record: no format change. The 256 capture bytes hold one 8-byte slot per field, the value
  extended to 64 bits (UBYTE zero-, the rest sign-extended, the ret_hi rule), big-endian.
  Follow rule (td_layout_follow_refusal, record.c): PTR_RAM (null, < 0x80000000, >= 0x400,
  even) and the structure's end <= 0x80000000; otherwise nothing is read and every slot behind
  it is 0xB0F3B0F3_000000NN (N = reason). tosdiff judges each slot by the field's class from
  the table (EXACT between the dumps, NONZERO/HANDLE/PTR_RAM per side, IGNORE not); a not-read
  slot prints its reason. A buffer read through a layout is poisoned per field type, so an
  untouched field (Getmpb's mp_rover) reads 0xFFFFFFFFDEADDEAD on both machines.
  Write: "!write return" admits "+put <field>=<field>" right after an r:<layout> case; copies
  one top-level non-pointer field onto another of the same type, only through a pointer the
  follow rule admits; the outcome is logged by DUMPBIOS after the run.
  Getmpb (13:0) leaves the excluded list: b: buffer, inside a Super bracket, last (as the
  bios-core audit's probe ran it, measurement-2026-10-28-bios-core-audit/RUNINFO.TXT group G).
