Failures (reproducing command)

F1. The contract check reports a false violation on a table that is not a contract table. At vdiplanes=32, `cargo xtask tosdump vdi tosdump/cases/vdi-v18.tsv --out <dir> --bootargs vdiplanes=32
    --reference tosdump/reference/EMUTOS-1a7484ab-VDI-v18-falcontc.BIN` ends with "contract check ... exit 1, 4 of 19 cases differ from the NewTOS contract" (cases 29, 32, 43, 59:
    v_get_pixel of a white / cleared pixel, "contract 0x0000, recorded 0x00FF / 0xFFFF"; serial/wt-v32/vdi-v18/contract32-check.txt). The recorded {0x00FF,0xFFFF} is the correct wide answer
    for a white pixel (V65 section 6; the receipt's own first-step table lists these cases as 0 -> {00FF,FFFF}); the checker's is_palette_table()/check_palette() (tosdump/host/contract32-check.py:517,561)
    take any table of only vq_color/v_get_pixel ops as vdi-a131-palette and assume every v_get_pixel reads the pixel the preceding vr_recfl pen painted (default pen 1 = 0), which only holds for
    that table. Effect: a correct kernel is reported red in a normal documented run. The developer's gate did not show this line (its list says only the INFORMATIONAL mark for the 16-plane tables).
    Fix direction (developer's call): restrict the check to the tables it models (by name or by an explicit marker), or model the unpainted pixel; the other tables correctly end exit 3.
