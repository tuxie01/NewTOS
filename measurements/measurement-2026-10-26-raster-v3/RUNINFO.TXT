METHOD
------------------------------------------------------------------------------
  method/run-raster-v3.sh <abs runs dir>
      copy of the ref07-v3 run-v3.sh, reduced to the two RASTER rows; one
      Hatari session per table via tools/hatari-oracle.sh:
        RASTER                  tt        vdi-raster.tsv          fdf8
        RASTER-screen-falcontc  falcontc  vdi-raster-screen.tsv   c1f4
      runs/<table>/ keeps RASTER.BIN, RASTER.LOG, hatari.log; the hd/
      staging directories were moved to the scratch area.
  method/exactcheck.c
      the replacement condition, compiled against tosdump/core/record.c.
      Header (32 bytes) excluded and reported. The address exclusion set is
      derived from the descriptors, not listed by hand: every field of
      td_area_fields(area) with compare == TD_FIELD_ADDRESS, and in it only
      its address CELLS (td_addr_cell_count / td_addr_cell_words), with the
      cell geometry from the format 3 header (pointer 4 bytes, MSW first),
      applied to both files (the format 2 LOG states the same: "pointer 4
      bytes, MFDB pointer slots at contrl[7] and [9]"). WORDs of an address
      field that are no cell (contrl[11..14] and contrl_before[11..14] at four
      bytes per pointer) stay COMPARED. Exit 0 only if no other byte differs.
  method/compare-raster-v3.sh <v2-dir>
      builds exactcheck, runs it per table (-> exactcheck/<table>.txt), runs
      tosdiff on each EmuTOS v3 recording against itself (-> tosdiff/<table>-self.txt),
      on the NewTOS v3 recording against itself (-> tosdiff/newtos-self.txt) and
      EmuTOS v3 RASTER vs NewTOS v3 (-> tosdiff/newtos-vs-emutos.txt). Files are
      copied to distinct names first so tosdiff's labels tell the sides apart.
  <v2-dir> = copies of tosdump/reference/EMUTOS-1a7484ab-RASTER*.{BIN,LOG}
  from the clean tree at 6ce7b877, taken before the replacement:
    EMUTOS-1a7484ab-RASTER.BIN                 cd68310a4022b0e391481dc0d86fd41e97d816461f800af9473d96a8f7d9beee
    EMUTOS-1a7484ab-RASTER.LOG                 18c4759a7941c7c25747af146e48f58acf65f5c60fc5d491da9a65255fb46596
    EMUTOS-1a7484ab-RASTER-screen-falcontc.BIN 70fbf432678d65e0d7a1c4ed01d41c43d9788c4ec2243bccba0dfc60ec0be406
    EMUTOS-1a7484ab-RASTER-screen-falcontc.LOG 8cee62413278d132dcdd4a4c1796cd25025d93471bf9cc0d030d45cd093ecea3
  (they stay in git history; not copied into this run).

  RASTER                  4 / 236                              944 of 218064   472               0                  PASS

  The four excluded cells per record, from the descriptors:
  contrl_mfdb cells 0 and 1 = contrl[7..8], [9..10] (record bytes 22..29),
  contrl_before_mfdb cells 0 and 1 = contrl_before[7..8], [9..10] (52..59).

  user's contrl[8]/[10] plus their high WORDs; with eight-byte pointers
  contrl[7..10] and [11..14].

  3. tosdiff change (tosdump/host/tosdiff.c; docs/TOS-REFERENCE-DUMPER.md
     section 3, "The kept check")
     kept_pairs names the pair (VDI-RASTER: contrl_mfdb / contrl_before_mfdb),
     resolved against the descriptors -- a pair that does not resolve to two
     address fields of one shape makes tosdiff refuse (exit 2). Cells and
     their values come from td_addr_cell_count / td_addr_cell_value, so the
     check follows each dump's own pointer width and word order. Own verdict
     line per dump ("kept check, <dump>: format 3; contrl_mfdb against
     contrl_before_mfdb, K cells checked, C changed by the call"), violations
     printed under the case as "... KEPT <dump> = 0x..., before the call
     0x...", not counted as a value difference; exit 1 on a violation;
     format 2 -> "not checkable". Tests: tosdump/tests/test_tosdiff.sh (clean
     pass, a changed after-cell, the same change on both sides, a changed
     before-twin, format 2 not checkable); a mutation that disables the
     comparison makes 7 of them fail.
