SPLIT SOUNDNESS (question of the lead)
  The split is sound for what it claims, with one residual gap. Seam 1 (USBSNAP_TEST_SNAPCALL) swaps only the 3-line snap_call (gemdos3 -> Ssystem 2022);
  seam 2 (USBSNAP_TEST_SINK) swaps only the six out_* file primitives. Everything else (list, strings, recording loop, counters, MUTE handling, file
  naming, collision rule, all of §4.4 content, section writers, line wrapping) is the SAME source in all three builds. qemu-virt therefore tests the
  real kernel answers with the real program logic; raspi4b tests the real out_* code (Fattrib/Dcreate/Fopen/Fcreate/Fwrite) against a real FAT driver
  and fsck. The two halves are joined by the raw kernel bytes (mkreplay.py). Residual gap: no single build ran real snap_call + real out_* + a recording.
  I closed part of it: the UNMODIFIED product binary (NAP bytes == NCP bytes, sha256 e46feb9d...) booted on qemu-virt as NEWDESK.NAP (serial/
  virt-product-unmodified.log, screendumps/virt-product.png): real Ssystem(2022) LIST + DEVICE with strings, device list, then the real folder check
  fails (no C:) -> "Cannot use the folder C:\USB\ : -34 (EPTHNF)", "No file was written." -- and the product binary on raspi4b (No USB controller path).
  What no QEMU run can do: the product binary through a real recording + real Fcreate/Fwrite in one run -> real Pi (T8). Replay answers are rebuilt headers
  (clock = one tick per call), so timing fidelity of the replay is not evidence for the kernel's timing; the kernel timing is the qemu-virt half.

FINDINGS / OBSERVATIONS (none changes a verdict)
  1. Race window in Store::mute_state (code reading, NOT reproduced): mute_seen is reset only by a poll that sees "not muted". MUTE off immediately followed by
     MUTE on within one 5-ms poll gap would not count as a new mute start (no release). USBSNAP's own sequence cannot do that (seconds apart); only a
     different client could. Informational.
  2. The all-skipped case prints "Done. Wrote:" followed by five "exists already - file skipped" lines and then "No file was written." (also names only the
     last tried candidate .T99). Cosmetic wording; behaviour correct.
  3. QEMU 'usb-tablet' shows as role 3 "HID (report)" and gets file + reports, no pointer effect: as specified (T5).
  4. 5 xtask tests need gitignored inputs (references/emutos/aes/gem.rsc, sdk/apps/teradesk/cicons.rsc): they fail in a clean git worktree; unrelated to USB01.
  5. A role-5 file produced by my patched replay still carries reports because the patch left ring_iface set; the "not recorded" text for ring 0xFF was
     therefore verified on a real role-0 device (usb-storage) instead. A genuine role-5 device cannot be produced in QEMU.
