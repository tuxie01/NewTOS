STEP A -- WHICH DEPTH THE PI USES, WHAT SELECTS IT, AND WHETHER TERADESK GATES COLOUR ICONS ON IT
  1. Physical framebuffer: always 32 bpp XRGB8888. The VideoCore mailbox request sets depth tag
     0x00048005 to the constant DEPTH_BPP = 32 (kernel/src/drivers/bcm2711/framebuffer.rs:34@DEPTH_BPP,
     kernel/src/drivers/bcm2711/framebuffer.rs:243-247@DEPTH_BPP in build_request), pixel order BGR,
     alpha mode "ignored". Only the geometry is taken from the firmware: init asks the current physical
     size (query_physical_size, kernel/src/drivers/bcm2711/framebuffer.rs:311@query_physical_size;
     kernel/src/drivers/bcm2711/framebuffer.rs:476@init), fallback 1920x1080
     (kernel/src/drivers/mod.rs:31@BOOT_WIDTH).
  2. VDI/AES device: always 16 planes, Falcon RGB565 truecolor over the 32-bpp store (ADR-024,
     docs/MEMORY.md). kernel/src/vdi_backend.rs:44@PLANES (const PLANES = 16) is what planes() returns
     (kernel/src/vdi_backend.rs:465@planes); vq_extnd reports the same (tos-api/src/vdi/eddi.rs:52@DEVICE_PLANES).
  3. Colour-icon selection: fix_cicons asks CiconDevice::live, which takes gl_nplanes from the raster
     backend = 16 (tos-api/src/aes/resource.rs:3075@live); best_match then picks the deepest variant
     not deeper than 16 (tos-api/src/aes/resource.rs:3241@best_match, EmuTOS gemrslib.c:267-282), i.e.
     the 4-plane variant of TeraDesk's cicons.rsc (TASK/A41-STATUS-DONE.MD part 1), transformed into the
     16-bit device form (tos-api/src/aes/resource.rs:3290@fix_cicons). No depth threshold exists in NewTOS.
  4. Settings: NO config.txt, cmdline.txt, NEWDESK.INF or TERADESK.INF setting selects colour depth.
     boot/rpi4/config.txt:15-16@hdmi_mode (hdmi_group=2, hdmi_mode=82) selects only the HDMI mode
     1920x1080; gpu_mem=256 (boot/rpi4/config.txt:25@gpu_mem) is needed for the framebuffer at all.
     kernel/src/bootargs.rs has no video token (serial, memprot, asid, emmc, cpuclk, input,
     bcache, bcachepct, mdlimit only).
  5. TeraDesk's gate (vendored sources sdk/apps/teradesk/, untracked, line cites): TeraDesk loads
     cicons.rsc only if `colour_icons` is set (sdk/overlays/teradesk/icon.c:2745-2753@colour_icons;
     upstream sdk/apps/teradesk/icon.c:2724-2733), and falls back to icons.rsc otherwise or when
     aes_supports_coloricons() fails (icon.c:2669-2697: tree 0 object 1 must be G_CICON with a non-zero
     ob_spec that is not ap_rscmem). `colour_icons` comes from appl_getinfo(2) only if has_appl_getinfo()
     (sdk/apps/teradesk/library/xdialog/xdialog.c:2259-2274: AES >= 0x400 or appl_find("?AGI") >= 0);
     NewTOS reports AES 0x0340 (tos-api/src/aes/appl.rs:114@AES_VERSION) and appl_find knows no "?AGI"
     (returns -1), so TeraDesk takes its fallback branch xdialog.c:2446-2451: TOS >= 0x400 and AES >= 0x330
     -> colour_icons = TRUE. NewTOS os_version is 0x0404 (tos-api/src/bdos/process/loader.rs:1082@OS_VERSION),
     read by the overlay's get_tosversion (sdk/overlays/teradesk/library/utility/gettos.c:52@get_tosversion).
     TeraDesk itself checks no plane count for loading (xd_nplanes, xdialog.c, is only stored).
  CONCLUSION: the owner's card needs no special setting; the default (32 bpp physical, 16 VDI planes,
  1920x1080) shows colour icons provided C:\Apps\TERADESK\cicons.rsc is the v13 conversion (ee7de7f3...).
  The card had exactly that file on 2026-11-04 (measurements/measurement-2026-11-02-proc08-pi/card-check/inventory.txt).
  Directory windows show icons only in TeraDesk's icon mode (options mode=1, ICONMODE, desk.h:74); the
  generated TERADESK.INF has mode=1; the sheet tells the owner to switch View -> Show as icons otherwise.
