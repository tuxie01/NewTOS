measurement-2026-11-04-a128 -- A128: file selector slider (FSVSLID page, FSVELEV drag), wheel, graf_slidebox
================================================================================================
Developer, TASK/A128, 2026-11-04 (host clock CET). Base HEAD bcffca60 plus the uncommitted A128
change set (tos-api/src/aes/{fsel,graf,input,object,window,mod}.rs, tos-types/src/aes.rs,
tos-api/tests/aes_a128_slidebox.rs, tosdump/probes/sbprobe.c ...). QEMU only (raspi4b + virt) and
the pinned Hatari oracle. No real Pi, no real card, no GitHub. Not committed.
Spec: docs/api/aes/resource-fileselector.md section "A128" (decisions of 2026-11-04).

WHAT / WHY
  1. raspi4b, scripted IKBD injector: a click in the slider track beside the thumb (page 9 rows),
     a thumb drag (XOR outline, value conversion), wheel detents over the list, outside it and over
     the track, selection dropped on scrolling -- in a real fsel_exinput dialog.
  2. virt, the REAL USB path (QMP input-send-event -> usb-mouse -> xHCI -> usb::poll -> hid ->
     ikbd::feed -> mousexvec -> wheel_change): wheel over the list, outside it, over the track.
  3. graf_slidebox against the pinned EmuTOS oracle: tosdump/probes/sbprobe.c (permanent probe),
     13 cases, run on both sides.

INJECTOR
  tools/inject-arm.py (the successor of the measurement-2026-09-17-h03 injector, which its own
  docstring retires for new runs: it arms on a program identity instead of "some EL0 program"),
  trigger launch:FSPROBE, scripts method/s-cal.script, method/s-main.script (generated by
  method/gen-script.py from absolute screen targets). Patched into a SCRATCH copy of the tree
  only (method/build-kernel.sh); the shared tree is never touched.
  Also in the scratch copy only: method/trace-patch.py adds `[a128]` serial lines (each detent
  the selector's claim consumes with the pointer and counted/dropped; each wheel take, slider
  page, thumb drag value, top row before/after). They go to the kernel's serial writer only
  (kprint!), not to the screen. The first attempt wrote them through the AES host console and
  they showed on the screen; that run was discarded and is not kept.

CAVEATS
  QEMU timing is not the Pi's; the injector feeds on a 5 ms grid; virt has no drive, so the
  visible scroll by the wheel is shown on raspi4b (injected wheel scancodes 0x59/0x5A enter at
  ikbd::feed, the same point the USB HID path feeds), the USB wheel path on virt only by the
  serial trace. Real Pi 4: acceptance through the tester scenario (TASK/A128 step 3).
