## Sachverhalt

`tos-api/src/aes/object.rs`, Textzweig von `just_draw`: `let mut th = ted.te_thickness;`
— ohne EmuTOS' `if (th > 128) th -= 256;` aus `ob_sst` (`aes/gemobjop.c`,
`ObjTree::sst_th` hat es fuer den Kastenzweig). Ein TEDINFO mit
`te_thickness = 255` (die uebliche Kodierung fuer −1 in RSC-Dateien, die das
Feld als Byte fuehren) wird +255 statt −1: ein 255 Pixel breiter Innenrand.

## Arbeit

Vorzeichenfaltung an derselben Stelle wie im Kastenzweig; Hosttest mit
`te_thickness = 255` → Aussenrand 1 px. Pruefen, ob unser RSC-Konverter
(`tools/mkrsc.py`) das Feld je als 255 durchreicht oder schon faltet.

## Abschluss (2026-09-20)

Textzweig von `just_draw` holt `th` ueber `ObjTree::sst_th(obj)` — die eine
Faltungsstelle (`if (th > 128) th -= 256`, `aes/gemobjop.c:68-69`), die der
Kastenzweig schon nutzte; `te_thickness = 255` → 1-px-Aussenrand, `effect_th`
ebenfalls gefaltet. `tools/mkrsc.py` faltet nicht (Spec (a)), 255 kommt an;
kein ausgelieferter Baum traegt heute 255. Hosttests rot-vor/gruen-nach
(`tos-api/tests/aes_object_3d_text_button.rs`), `xtask test` 680 → 688/0/1,
rpi4 64/94, neun QEMU-Screendump-Paare vorher/nachher bytegleich. Kein Commit
(Lead). Belege: [`A68-STATUS-DONE.MD`](A68-STATUS-DONE.MD),
`measurements/measurement-2026-09-20-a68-a70/`. **Offen:** Sichtabnahme auf der Pi 4.
