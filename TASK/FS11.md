## Sachverhalt

NewTOS leitet in `tos-api/src/bdos/fs/file.rs` (`fread`, `fwrite`) jedes
Zeichengeraet-Ziel auf die Konsole. EmuTOS unterscheidet im
Handle-Aufloesungsblock von `osif` (`bdos/bdosmain.c:571-642`, Pin
`1a7484ab`):

- `Fwrite`: CON (-1) ueber `tabout`, AUX (-2)/PRN (-3) ueber `Bconout`;
  liefert `Bconout` 0, endet der Aufruf mit der Zahl der bis dahin
  geschriebenen Bytes (`:622-639`).
- `Fread`: Laenge mit gesetztem hohen Wort (`pw[2] != 0`, „HUGE read“) → 0;
  ein Byte → `conin`; sonst `cgets` auf dem jeweiligen Geraet (`:608-620`).
- Standard-Handle 2 zeigt per Vorgabe auf AUX, 3 auf PRN
  (`bdos/console.c:60-67`).
- Erweitert 2026-10-13 (Nebenfund LIBC-MAIN): `console_read` in `file.rs`
  liest auf CON genau `len` Bytes blockierend; EmuTOS liest per `cgets`
  eine Zeile (Ende bei Return, Laenge = gelesene Zeichen). Gehoert in
  denselben Zeichengeraete-Weg.

## Nachtrag 2026-10-13 — AUX als „Port da, kein Kabel“

Die Abnahme (`measurements/measurement-2026-10-13-libc-main-fs11-acceptance/RUNINFO.TXT` §1)
fand: mit AUX als fehlendem Geraet liefert `Fwrite(2,…)` 0, mintlibs
Schreibschleife wiederholt endlos; jedes vor `7e04c872` gelinkte
libc-Programm haengt beim ersten stderr-Schreiben. Anwenderentscheidung
(Option A): der AUX-Eintrag nimmt Bytes an und verwirft sie (`Bconout(1)`
= 1, `Bcostat(1)` = -1, wie EmuTOS' `bconout1`/`bcostat1` mit MFP-Port,
`bios/serport.c:271-330`); `Bconin(1)`/`Bconstat(1)` bleiben 0 ohne
Blockieren. PRN und MIDI bleiben „nicht vorhanden“. Neuer Schutztest W28.
