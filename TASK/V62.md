# V62 — VDI 32 planes: boot setting `vdiplanes` and the VDI depth as a boot-time value

Status: OPEN (2026-11-18) | Priority: P2

Title: VDI 32 planes: boot setting `vdiplanes` and the VDI depth as a boot-time value

Type: developer, then tester. Owner decision 2026-11-18 (TASK/V61.md): both VDI depths, selectable at boot, 16
planes the default; ADR-038 is the contract for the 32-plane setting. Slice of the series V62-V69 cut from the
ADR draft of TASK/V61.md (step 2, section D). Building starts on the owner's word.

## Scope

ADR-038 points 1-3. The boot argument `vdiplanes=<16|32>` in `cmdline.txt` (absent or invalid = 16, invalid with a
boot line), read once at boot through the existing boot-switch mechanism; `planes()` becomes a boot-time value in the
three places that hold the constant 16 today (kernel raster backend, `tos-api` raster, EdDI) and at the `vq_extnd`
gate; the `vq_extnd` and device-table answers and `ap_planes` of point 3.

Sources: ADR-038 in `docs/MEMORY.md` (the contract; where it generalises an EmuTOS rule it cites the rule),
`docs/analysis/vdi-32bit-scope-2026-11-18.md` §1.2 (the change sites by file and function), TASK/V61.md step 2.
Before code: the spec files under `docs/api/vdi/` that this slice changes are extended for the 32-plane
setting (spec gate, researcher), since no EmuTOS path exists above 16 planes.

Depends on: none (first slice).

## Acceptance

- Without the argument, and with `vdiplanes=16`: every existing host test, case table and screendump is unchanged
  (byte-identical kernel behaviour is the bar: the full XBIOS and VDI case runs show no changed verdict).
- With `vdiplanes=32`: `vq_extnd` and `appl_init` report 32 planes as ADR-038 point 3 lists; an invalid value boots at
  16 with the boot line.
- The drawing result at 32 is not part of this slice (it follows in V63-V67); the slice says in its receipt what a
  32-plane boot shows until then.
- `cargo xtask test` green; both board builds; warnings delta 0; doc-check of the edited docs 0 failures.
