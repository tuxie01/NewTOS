## Fix (Developer, 2026-11-06)

`tos-api/src/vdi/raster.rs`:
- `Mfdb::mem_stride_px` = `fd_wdwidth * fd_nplanes` WORDs (`setup_info` `s_nxln`/`d_nxln`,
  `vdi_raster.c:919-940`; `vro_cpyfm16`/`vrt_cpyfm16` `:986-987,1249`). Damit nutzen
  `mem_index`/`row_cols`/`mem_span_px`/`chunky_hull`/`bind_block` — also auch die V26-Bindung —
  die neue Zeilenlaenge; bei 16 Ebenen (`device_mem`, AES) unveraendert.
- `vrt_cpyfm`: Speicherziel mit 1..8 Ebenen → planarer Blit (`planar_blit`, aus
  `planar_mem_to_mem` verallgemeinert: Op je Ebene, eine Quellebene unter jeder Zielebene,
  `s_nxpl = 0`), Op je Ebene `vrt_planar_op` = `op_tab[(fg-Bit << 1) | bg-Bit]` (`:744-746`,
  `:1397-1430`), Farben ueber `map_col` = EmuTOS `MAP_COL` (`vdi_col.c:28-29,736-742`; die
  Registerbits landen in der Form, die `MAP_COL`-Faltung der Palette gilt hier nicht). 0 Ebenen
  zeichnen nichts; gebunden wird `bind_planar_block`.
- `mem_to_mem`: Richtung wie `vro_cpyfm16` (`:989-1002`): rueckwaerts (letzte Zeile, letzter Pixel
  zuerst) genau dann, wenn der Startzeiger der Quelle unter dem des Ziels liegt (`chunky_reverse`);
  vorher NewTOS-eigene Regel (offener Punkt aus V26), messbar bei 9..15 Ebenen (Faelle 44–45).

Grenze V26 bleibt: nichts hinter den `fd_h` Zeilen der Form. Weil eine 16-Pixel-Zeile einer Form
mit 9..15 Ebenen laenger ist als die Zeile der Form, laeuft ein Block ueber die ganze Form an ihr
Ende hinaus; dort schreibt EmuTOS, NewTOS nicht. Die Faelle 28, 29, 33, 34, 35, 37 unterscheiden
sich deshalb nur in diesen Woertern hinter der Zielform (`buf_b[144..150]`, `[192..195]`,
`[240]`, `[384..391]`).

Spec `docs/api/vdi/raster/_raster.md`: neuer Abschnitt "Memory destination: planar below nine
planes, chunky above (V28)" unter `vrt_cpyfm`; Row geometry, Tabellenzeile `fd_w`/`fd_h`, Pixel
offset und Edge case 5 (Richtung `vro_cpyfm16`) EmuTOS-konform berichtigt (die Spec nannte 9..15
Ebenen "open since V19"). `docs/COMPATIBILITY.md` Formende-Eintrag auf `fd_nplanes`
verallgemeinert. mapping-Zeilen: `setup_info` → `mem_stride_px`/`mem_span_px`,
`vro_cpyfm16` → `mem_to_mem`/`chunky_reverse`, `cpy_raster` → `vrt_cpyfm`/`vrt_planar_op`,
`bit_blt`/`fast_bit_blt` → `planar_blit`, `init_colors` → `map_col`/`ensure_palette_init`;
`cargo xtask deps --check-mapping` sauber.

Tests: `tos-api/tests/vdi_raster_reference_v18t2.rs` + generiertes
`tos-api/tests/vdi_raster_reference/cases_v18t2.rs` (mkrusttests, alle 26 Faelle der Tabelle):
