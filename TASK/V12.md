## Abschluss

Korrigiert wurde ausschließlich der in V11 belegte Produzent — das
Kernel-Gerätepixelmodell (2026-09-21, Branch `desk-rebuild`, Basis HEAD
`194b057`, nicht committet, nichts geflasht); keine ODER-Maske auf
`v_get_pixel`, keine Farbengine-Neufassung:

* `kernel/src/vdi_backend.rs`: `word_to_device` / `device_to_word` — das
  16-Bit-Bildschirmwort wird feldweise ins 32-bpp-Wort expandiert: 5→8 Bit je
  Kanone (unverändert) und `OVERLAY_BIT` in alle acht X-Bits repliziert
  (`0xFF` gesetzt / `0x00` frei); zurück die obersten 5 Bit je Kanone und das
  oberste X-Bit. `rgb565_to_device`/`device_to_rgb565`/`pel_to_rgb`/`read_pixel`
  benutzen das Paar; `xor_pixel` komplementiert alle 32 Bit, wie EmuTOS
  `~temp` das ganze Wort (`vdi_line.c:494,501,1670,1730`,
  `vdi_textblit.c:806,1120`); die 16 `vro_cpyfm`-Operationen (`raster_op`)
  auf dem 32-Bit-Wort sind dadurch dieselben auf dem 16-Bit-Wort.
  `kernel/src/hal/framebuffer.rs`: `rgb()` packt X = 0, Modul-Doc = der
  X-Byte-Vertrag. Spec: `docs/api/vdi/workstation/03-v_clrwk.md`
  (Füllbyte „irrelevant" / „PEL 0 via fill_rect" berichtigt),
  `docs/api/vdi/raster/_raster.md` § „Pi/BCM2711 binding" (Feldtabelle).
* Test-Doubles nachgezogen: `tests/vdi_reference/overlay_bit.rs`
  (Transkription mit Zeilenangaben), `tests/vdi_reference/harness.rs`
  (vorher sechs Grünbits).

Prüfung: V11-Test **vorher 3 rot / 1 grün, nachher 4 grün**; Schwarz
(`0x0000`, Fälle 270/272), Weiß (`0xFFDF`, Kontrolltest), Bit-5-Kanten
(`0xFFFF` ↔ `0xFFDF`, XOR `0xFFDF` ↔ `0x0020`) und alle bisher richtigen
Farben bleiben richtig: `cargo run -p xtask -- test` **841 / 0 / 1**;
`cargo xtask build --board rpi4` tos-api 64 / kernel 94 (unverändert), Clippy
ohne Meldung in geänderten Dateien. QEMU raspi4b (Release-Kernel, `#Z`-Dumper):
`tosdiff` gegen `EMUTOS14-VDI-all-falcontc.BIN` **0 von 182** (vorher 3),
gegen den NewTOS-Dump vom Vormittag genau die drei Zellen `0xFFDF → 0xFFFF`;
Raster 1 von 59 (Fall 157, D-VDI-25, unverändert), byteidentisch zum vorigen
Raster-Dump; Desktop- und TeraDesk-Idle-Screendumps Vorher-/Nachher-Kernel
byteidentisch (`measurements/measurement-2026-09-21-v11-v12/`).

**Offen — die Abnahme verlangt eine neue Pi-Messung:** nicht geflasht
(Lead/User). Zu prüfen auf der Pi: `DUMPVDI` Fälle 54/160/161 = `0xFFFF`
**und** ein unverändertes Bild (das VideoCore-Verhalten zum obersten Byte bei
Tiefe 32 steht in keiner Track-B-Quelle; falls es Alpha auswertet: Tag
`0x0004_8007` = „alpha ignored" im Allokations-Telegramm, nicht gesendet,
weil nicht belegt). Quittung: [V12-STATUS-DONE.MD](V12-STATUS-DONE.MD).
