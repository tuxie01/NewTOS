# V69 — VDI 32 planes: tosdump at 32 planes and the program patches

Status: OPEN (2026-11-18) | Priority: P3

Title: VDI 32 planes: tosdump at 32 planes and the program patches

Type: developer, then tester. Owner decision 2026-11-18 (TASK/V61.md): both VDI depths, selectable at boot, 16
planes the default; ADR-038 is the contract for the 32-plane setting. Slice of the series V62-V69 cut from the
ADR draft of TASK/V61.md (step 2, section D). Building starts on the owner's word.

## Scope

ADR-038 point 13 (iii) and (iv): the tosdump caps at 16 planes lifted, 32-plane expected values from ADR-038 labelled
"NewTOS contract", never "oracle"; program acceptance at 32 planes (zView, HighWire, DOOM); the patches the owner
decides for programs that break at 32 (TeraDesk's 17-entry table indexed by the plane count, `present`'s hardwired 16,
HighWire's 8-byte `ULONG`), each as a patch file in `sdk/overlays/`, upstream unchanged.

Sources: ADR-038 in `docs/MEMORY.md` (the contract; where it generalises an EmuTOS rule it cites the rule),
`docs/analysis/vdi-32bit-scope-2026-11-18.md` §1.2 (the change sites by file and function), TASK/V61.md step 2.
Before code: the spec files under `docs/api/vdi/` that this slice changes are extended for the 32-plane
setting (spec gate, researcher), since no EmuTOS path exists above 16 planes.

Depends on: V62-V68.

## Acceptance

- The 16-plane tables still compare against the pinned oracle unchanged; the 32-plane tables run and are labelled as
  NewTOS contract.
- Per program: it shows a correct image at 32 planes, or the owner has decided it stays a 16-plane program (listed in
  `docs/DEVIATIONS.md`).
- Measured and recorded: zView's path at 32 planes.
- `cargo xtask test` green; both board builds; warnings delta 0; doc-check of the edited docs 0 failures.
