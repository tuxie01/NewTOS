# FS33 — Zweiter Handle auf eine wachsende Datei sieht Laenge 0

Status: **OFFEN** (2026-11-06) · Prioritaet: **P3** · Typ: Abweichung, am Orakel gemessen — aus [HW08](HW08.md)

Datei angelegt, 5000 Byte geschrieben, noch offen, zweiter `Fopen`: EmuTOS teilt den Dateideskriptor und liefert Laenge 5000, `Fread` 5000. NewTOS liefert 0 und 0 (`measurements/measurement-2026-11-06-hw08-fix/RUNINFO.TXT`). Bestand schon vor dem HW08-Fix.

Dazu aus demselben Lauf, gelesen oder gemessen, gleiche Gegend: `Dcreate` nimmt seinen Eintrag bei gescheitertem Rueckschreiben nicht zurueck; ein Handle wird nach gescheitertem `Fclose` frei, EmuTOS laesst ihn belegt (Anwenderentscheidung offen, COMPATIBILITY benannt); scheitert das `Fclose` beim Prozessende am Verzeichniseintrag, ist die Laenge ohne Meldung verloren.

Auftrag: Karten-Apps mit diesem Muster suchen (Wirkung zuerst), dann Fix wie EmuTOS `DFD`.
