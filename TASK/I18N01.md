# I18N01 — internationalize the user-visible NewTOS text

Status: PARKED (2026-11-11) | Priority: P3 | Reason: larger project, owner decision 2026-11-11 | Reopen: after API alignment (BIOS/XBIOS/GEMDOS/AES/VDI) is complete, owner decides

Type: project (research, design, refactor). Owner decision 2026-11-11: filed parked, not started.

## Goal

Internationalize all user-visible NewTOS text — kernel, tos-api, AES, desktop, and the RSC dialogs and menus — with
the language selectable.

## Known today

From the COOK02 facts report (`docs/analysis/cook02-country-facts-2026-10-30.md`): system texts are English only,
there is a single font set, and the country is fixed to US; the strings are hard-coded in the source.

## Planned steps when reopened

1. **Inventory** (researcher, read-only): count and locate the user-visible strings per layer, RSC files included; how
   EmuTOS does it (`.po` catalogs, per-language RSC, country chosen at build time).
2. **Design** (an ADR): catalog format, string keys, runtime lookup, charset and font coverage (Atari charset,
   umlauts), RSC per language.
3. **Refactor** file by file: literals become keys.
4. **Guard/hook:** reject new user-visible literals outside the catalog; tests for missing or outdated translations and
   for text length against dialog size.
5. **Translations** proposed by agents, reviewed by a human.
