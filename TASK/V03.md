## Abschluss

Geräteparameter, belegt und getestet (2026-09-21, Branch `desk-rebuild`,
Basis HEAD `194b057`, nicht committet):

* **Soll:** `DEV_TAB[39] = get_palette()` (`vdi/vdi_control.c:208`); auf einem
  VIDEL „the same values as Atari TOS 4.04“: `(mode & VIDEL_COMPAT) ||
  ((mode & VIDEL_BPPMASK) == VIDEL_4BPP)` → 4096, sonst 0
  (`bios/screen.c:840-846`); die TT-Shifter-Pfade liefern 4096
  (`:850-866`). **Gemessen:** EmuTOS 1.4, dasselbe ROM, TT-Medium 4096,
  Falcon030 VIDEL-Truecolor **0** (`tosdump/reference/EMUTOS14-VDI-all-falcontc.BIN`,
  Fälle 33/274; `measurements/measurement-2026-09-21-vdi-qemu/cells.txt`). Der Pi-Wert 0
  ist damit EmuTOS' eigener Wert für das Truecolor-Profil (ADR-024).
* **Nicht fest verdrahtet:** `tos-api/src/vdi/workstation.rs`
  `palette_precision(planes)` ersetzt die Konstante `PALETTE_PRECISION = 0`
  — 4 Planes → 4096, jede andere Tiefe (1/2/8/16) → 0, mit dem Hinweis, dass
  das ST-Kompatibilitätsflag (`:843`) durch eine Planezahl nicht darstellbar
  ist und NewTOS keinen ST-kompatiblen Modus hat; `init_wk` und `vq_extnd(0)`
  rufen sie. Unit-Test
  `vdi::workstation::tests::dev_tab_39_is_4096_for_four_planes_and_0_for_every_other_videl_depth`
  (16→0, 8→0, 4→4096, 2→0, 1→0); Harness-Formel `harness.rs::substitute`
  (`PLANES == 4 → 4096, sonst 0`) angeglichen; Byte-Vergleich gegen die
  Falcon-TC-Referenz in `cases_v_series.rs` (`v01_v02_v03_case_0033_…`,
  `v14_v15_case_0274_…`) grün. QEMU raspi4b: `DEV_TAB[39] = 0`, `tosdiff`
  gegen Falcon-TC 0 von 182 (`measurements/measurement-2026-09-21-v11-v12/`).

Keine Hardwareabnahme nötig (Wert gemessen und formelgleich; die Pi meldet
denselben Wert seit 2026-09-09). Quittung: [V03-STATUS-DONE.MD](V03-STATUS-DONE.MD).
