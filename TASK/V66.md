## Spec gate (researcher, 2026-11-18) and the lead's reading of its open points

Spec: `docs/api/vdi/eddi-vq_scrninfo-32.md` (full table, consistency table, self-test statements S1-S7, change set,
program survey). EmuTOS has no EdDI; the 32-plane values are NewTOS contract per ADR-038 point 8.

Readings the developer works with (each follows ADR-038 as accepted; nothing new is decided here):

1. `INTOUT[5..7]` stay 0 at 32 (ADR-038 point 8); a 64-bit address does not fit two words and no program in the tree
   reads them.
2. `INTOUT[14]` = 1: the bit numbers count the native 32-bit word, as in the approved 16-plane answer. The byte-wise
   reading of the NVDI text is not taken; no source decides it and the three programs that read the answer use the
   bit tables, not this word.
3. A program that sets a bit the table lists as unused sees it dropped on read (the read mask of TASK/V63.md).
4. The gate widens to plane counts 16 and 32 only.
5. S7 of the spec (pen drawn, read back, compared with the table-built pixel) goes beyond ADR-038 point 13 (i): the
   developer may add it as a test; it is not an acceptance criterion.
6. From TASK/V65.md, owner 2026-11-18: the round trip with a pixel built from the `vq_scrninfo` description closes
   here (S6).
