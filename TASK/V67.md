## Spec gate (researcher, 2026-11-18) and the lead's reading of its open points

Spec: `docs/api/vdi/raster/_raster.md`, section "32-plane setting: AES colour icons, the AES inventory, the order of
the change ... (V67)" (inventory L1-L12, rules I1-I11, order, change set), and `docs/api/bios/_vt52-32plane.md`
(rules C1-C7, change set). EmuTOS has a 16-bit rule only; the 32-plane rows are NewTOS contract per ADR-038 point 10.

Readings the developer works with (the acceptance criteria above are unchanged):

1. Icon pixel at 32: the pen pixel of TASK/V64.md (8 bits per gun, from the same colour triples as today), not the
   5-bit word replicated (ADR-038 points 4 and 10). The 16-bit expansion branch that TASK/V65.md put into the blit
   goes away with it; its test `the_colour_icon_blit_reads_its_16_bit_form_at_32` is replaced, not kept.
2. An exact 16-plane icon variant is expanded and masked at 32 and not at 16, so pixels under a clear mask bit may
   differ between the settings; accepted as not visible (the mask blit paints first). The tester states as a fact
   whether the colour-icon resource on the standard image holds 16-plane variants.
3. Docs: statements "one 16-bit RGB565 icon form" are corrected in the developer's commit where the file is English;
   a file that is German in the touched part is left alone and the spec section stands as the 32-plane statement.
4. Console colour before the first workstation opens: the default words expanded by gun replication, so the boot
   console looks the same at both settings (spec rule C3).
5. Cursor: complements all 32 bits, as the XOR of TASK/V63.md does (spec rule C4).
6. Order: loader pixel store, buffer bytes and cursor step, drawer span, blit stamp and palette entry change in one
   commit from one depth source; the VT52 writer's four functions change together. One feat commit for the ticket
   is fine as long as no intermediate state is committed.

Notes for the tester (method, not criteria):

- The plain image has no colour-icon resource; the booted colour-icon check needs TeraDesk and its `cicons.rsc`.
- `tosdump/probes/icprobe.c` reads the icon data as 16-bit words and cannot measure the 32-plane form before
  TASK/V69.md.
- Tolerance 16 against 32 per gun as in TASK/V64.md; the console screendump at default must equal `main`.
- `gsx_malloc` takes about 8.3 MB at 1080p and 32 planes; not checked on a board with a smaller pool.
