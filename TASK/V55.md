# V55 — Zeiger zeichnen im Bildtakt statt sofort beim Mauspaket

Status: **OFFEN** (2026-11-07; Anwenderentscheidung 2026-11-08: (a), Zeichnen im Bildtakt wie EmuTOS) · Prioritaet: **P4** · Typ: Abweichung, gemessen (VDI-WK-004) — aus [V18](V18.md) Teil 3

Nach einem Mauspaket zeichnet NewTOS den Zeiger sofort an der neuen Stelle; EmuTOS erst im naechsten VBL (`vb_draw`), `vq_mouse` meldet dort schon die neue Position. Hoechstens ein Bild lang verschieden, Endzustand gleich (wkprobe M1, M2). Entscheidung: (a) Zeichnen auf einen Bildtakt verschieben wie EmuTOS, (b) Eintrag in `docs/COMPATIBILITY.md`. Lokalisiert: `set_state`/`feed_relative`.

Befund: `docs/audits/2026-11-07-v18-t3-vdi-workstation.md` (VDI-WK-004), Lauf `measurements/measurement-2026-11-07-v18-t3/RUNINFO.TXT`.

**Entscheidung (Anwender 2026-11-08): (a).** Der Zeiger wird wie EmuTOS erst im naechsten Bildtakt gezeichnet (`vb_draw`); `vq_mouse` meldet die neue Position sofort. Abnahme: wkprobe M1, M2 orakelgleich; Maus auf der echten Pi im Testszenario (der Weg beruehrt IRQ/VBL). Vor Start lokalisieren (Lead).

## Lokalisierung (Lead, 2026-11-08)

`docs/analysis/deps/mapping.tsv`: `vb_draw` und `mov_cur` -> `tos-api/src/vdi/mouse.rs` `set_state` ("NewTOS draws inline
here, EmuTOS defers the draw to vb_draw on VBL"), `mouse_int` -> `feed_relative`/`update_ms_stat`, `cur_display` -> `draw`,
`cur_replace` -> `erase`. `cargo xtask deps mov_cur --up` / `mouse_int --up`: Schicht vdi vollstaendig, kein `unmapped`.
`vb_draw` hat im Graphen keine Aufrufer: EmuTOS haengt es in `vblqueue[0]` (`references/emutos/vdi/vdi_mouse.c:602`, `:631`),
Koerper `:647-690`; der NewTOS-VBL-Weg ist vom Developer aus dem Kernel zu belegen. Retest: wkprobe (M1, M2 und alle
Zeigerfaelle), Desktop-Szenen mit Injektor, USB-Maus auf der echten Pi (Tester-Szenario).
