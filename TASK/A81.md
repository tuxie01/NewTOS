Abhaengigkeiten: —

## Befund

EmuTOS `wm_set` `case WF_NEWDESK` (`references/emutos/aes/gemwmlib.c:1685-1689`):
`gl_newdesk = *(OBJECT **)pinwds` (32-Bit-Zeiger in `int_in[2..3]`),
`gl_newroot = pinwds[2]` (`int_in[4]`) — disjunkt.

NewTOS `set_newdesk` (`tos-api/src/aes/window.rs:1029-1063`) liest den Baum fuer
die gepackte Konvention ueber `intin_ptr(2)` (`tos-api/src/aes/mod.rs:317-338`):
bei LP64 **acht** Bytes = `int_in[2..5]`; den Root aus `int_in[4]` (`:1031`) —
das sind die Bits 32..47 des Zeigers. Die LP64-gemlib-Bindung schreibt genau
so (`sdk/gemlib/gemlib-0.44.0/a_wind_set_ptr_int.c:8-13`: `*(void**)(aes_intin+2)
= v; aes_intin[4] = W3;`). Root ≠ 0 zerstoert den Zeiger; Root = 0 geht nur,
weil Anwendungsadressen unter 4 GiB liegen (`kernel/src/arch/aarch64/el0.rs:48-57`).

TeraDesk uebergibt Root 0 (`sdk/apps/teradesk/icon.c:2511`), EmuTOS' eigener
Desktop `DROOT = 1` (`references/emutos/desk/deskmain.c:2049`,
`desk/deskwin.h:44`). Eine portierte Anwendung mit Root ≠ 0 registriert einen
falschen Baum.

Spec: `docs/api/aes/window-graphics.md:1385-1406` behauptet, der Zeiger komme
auf NewTOS **nur** in `addr_in[0]`; der Code faehrt eine Doppelkonvention
(`wf_str_ptr :2359-2365`, `AIN_LEN`-diskriminiert), und wo der Root fuer einen
LP64-gepackten Aufrufer liegt, sagt die Spec nirgends.

## Fall (A59 § 4, T9 + Scratch 2)

LP64-Baum an `0x0000_0001_0177_E4C0`, gemlib-Packung mit Root 2:
`int_in[2..5]`, wie `intin_ptr(2)` sie liest, ergeben `0x0000_0002_0177_E4C0`;
`wind_set(0, WF_NEWDESK)` liefert 1 und registriert den zerstoerten Zeiger.
(Auf dem Host ueberlebte der Repaint zufaellig; auf der Pi 4 ist
`0x2_xxxx_xxxx` fuer den Baum keine gueltige Adresse.)

## Arbeit

Konvention festlegen (Spec zuerst): fuer LP64-gepackte Aufrufer Root an einer
Stelle ausserhalb der acht Zeigerbytes (z. B. `int_in[6]`, `IN_LEN 7`) oder
die Bindung auf `addr_in[0]` + `int_in[2]` (die native Konvention) umstellen —
Kernel (`set_newdesk`) und `sdk/gemlib` (`a_wind_set_ptr_int.c`, ggf.
`a_wind_set_ptr.c`/`a_wind_set_str.c` fuer die Symmetrie) gemeinsam.
Hosttest: LP64-Packung mit Root 1 → registrierter Baum unveraendert
(rot vor dem Fix). TeraDesk-Overlay bleibt unveraendert (Root 0).

## Abschluss (2026-09-20)

Konvention: gepackt (`AIN_LEN == 0`) Root in `int_in[2 + ptr_words]` —
`int_in[4]` ILP32 (bitgleich EmuTOS), `int_in[6]` LP64; nativ (`AIN_LEN >= 1`)
`addr_in[0]` + `int_in[2]`. Kernel `set_newdesk` liest so (`Aespb::ptr_words`);
gemlib-Overlay `a_wind_set_{ptr_int,ptr,str}.c` sendet die native Form.
Hosttests rot-vor/gruen-nach (Modul + Integration + gemlib-Hosttest),
`xtask test` 674 → 680/0/1, Bibliothekskette und beide Apps linken, TeraDesk-
Hintergrund in QEMU vorher/nachher bytegleich. Kein Commit (Lead). Belege und
offene Punkte: [`A81-STATUS-DONE.MD`](A81-STATUS-DONE.MD),
`measurements/measurement-2026-09-20-a81/`. **Offen:** Sichtabnahme auf der Pi 4.
