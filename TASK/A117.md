# A117 — `menu_intercept` stellt MN_SELECTED an die aktuelle Identitaet statt an den Menue-Besitzer

Status: **ERLEDIGT** 2026-10-25 (QEMU, `eaf32b04`; echte Pi offen) — [Quittung](A117-STATUS-DONE.MD) · Prioritaet: **P2** · Typ: Abweichung von EmuTOS (vermutlich Defekt) — Nebenbefund aus GH1 (2026-10-21, `7b295ab3`)

## Befund (Developer, ungeprueft)

`menu_intercept` (`tos-api/src/aes/event.rs`) schreibt die MN_SELECTED-
Nachricht in die Queue der gerade laufenden Identitaet. EmuTOS stellt sie an
den Besitzer der Menueleiste (`gl_mnppd`; `aes/gemctrl.c`, `aes/gemmnlib.c`).
Laeuft der Inline-Control-Manager im `evnt_multi(MU_MESAG)` eines
Accessorys, landet eine Desktop-Menuewahl beim Accessory.

## Auftrag

Erst die Wirkung belegen (QEMU raspi4b, Injektor: Accessory offen und
wartend, dann Desktop-Menuewahl), Stelle gegen EmuTOS mit Datei:Zeile, dann
Fix nach EmuTOS mit Hosttest.

[Gemeinsame Regeln](README.md) gelten.

## Abschluss 2026-10-25

Befund bestaetigt. QEMU raspi4b mit Sonden-Accessory in `evnt_multi(MU_MESAG)`:
NEWDESKs *Desk → Desktop info…* und TeraDesks *File → Quit/Shutdown* landen
als `MN_SELECTED` beim Accessory, das Programm reagiert nicht (5/5 Laeufe);
nach dem Fix 0/5, Dialog erscheint. EmuTOS `aes/gemctrl.c:353,365`,
`aes/gemmnlib.c:707,712`. Fix `menu::mn_selected_target()` + `menu_intercept`,
Hosttest `tos-api/tests/aes_a117_mn_selected_owner.rs` (rot → gruen), Spec
`docs/api/aes/menu.md`/`event.md` ergaenzt. Commit `eaf32b04`, Beleg
`measurements/measurement-2026-10-25-a117/RUNINFO.TXT`. Offen: echte Pi 4.
