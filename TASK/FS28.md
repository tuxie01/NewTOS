# FS28 — `Dsetpath` nach Neuanmeldung: `E_OK`, aber `Dgetpath` liefert die Wurzel

Status: **ERLEDIGT** 2026-10-30 (Quittung [FS28-STATUS-DONE.MD](FS28-STATUS-DONE.MD), Beleg `measurements/measurement-2026-10-30-fs28/RUNINFO.TXT`) · Prioritaet: **P2** · Typ: Developer — Fund N1 aus [FS24](FS24.md) (2026-10-29)

## Sachverhalt (gemessen)

`tosdump/cases/gemdos-mc-fs24.tsv` Faelle 87, 118, 150: nach einem Medienwechsel
meldet `Dsetpath(C:\SUB)` das Laufwerk neu an, startet neu und liefert `E_OK`;
das folgende `Dgetpath` liefert `""` (Wurzel), das Orakel `\SUB`
(`measurements/measurement-2026-10-29-fs24/RUNINFO.TXT`). Der Aufruf meldet
Erfolg und setzt den Pfad nicht.

## Ursache (aus dem Code abgeleitet, Developer FS24)

- `free_drive` (`tos-api/src/bdos/fs/curdir.rs:332@free_drive`) laesst das
  PD-Byte auf den freigegebenen Slot zeigen.
- `set_curdir` (`tos-api/src/bdos/fs/curdir.rs:225@set_curdir`) nimmt zuerst
  einen Slot fuer den neuen Pfad — denselben Index —, liest dann das alte
  Byte, haelt es fuer lebendig und gibt den eben genommenen Slot frei.
- EmuTOS liest `olddir` vor `findit` (`references/emutos/bdos/fsdir.c:1129`,
  `:1134`), und `ckdrv` repariert das Byte vorher auf einen Wurzel-Slot
  (`references/emutos/bdos/fsdrive.c:121-130`).

## Lokalisierung (Lead, 2026-10-30)

- `xchdir` (`Dsetpath`) → `tos-api/src/bdos/fs/dirops.rs@dsetpath`; Slot-Verwaltung
  `tos-api/src/bdos/fs/curdir.rs@set_curdir`, `incr`, `decr`; Freigabe beim
  Medienwechsel `tos-api/src/bdos/fs/curdir.rs@free_drive`; `ckdrv` →
  `tos-api/src/bdos/fs/fat.rs@mount`.
- `--down` `xchdir`: alles `mapped` bis auf `extract_drive_number`,
  `strncasecmp` (Schicht ext, Hilfsfunktionen). Vollstaendig: ja.
- `--up` (Schicht bdos): `osif`, `enter`. `unmapped`: keine.
- **Erreichbarkeit auf rpi4 (Anwenderfrage, Lead 2026-10-30):** physisch kein
  Medienwechsel (SD gilt als nicht wechselbar, `tos-api/src/bios/mod.rs@media_change`;
  kein USB-Massenspeicher; `hdv_mediach`-Haken nach ADR-031 nie gerufen).
  Erreichbar ist FS28 auch auf der echten Pi ueber `Rwabs`-Schreiben auf den
  logischen Sektor 0 (setzt `forcechange`, wie EmuTOS
  `references/emutos/bios/blkdev.c:446-453`); danach Neuanmeldung des
  Laufwerks. Selten, aber still falsch; P2 bleibt (Anwender).
