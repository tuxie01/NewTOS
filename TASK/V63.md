## Scope

ADR-038 point 4 (pixel layout, X byte unused) and point 11: the device pixel `0x00RRGGBB` equal to the store word, the
clear value, the masks on every read path, `xor_pixel` and `read_pixel`; the raster kernels stay on `u32` pixels.

Sources: ADR-038 in `docs/MEMORY.md` (the contract; where it generalises an EmuTOS rule it cites the rule),
`docs/analysis/vdi-32bit-scope-2026-11-18.md` §1.2 (the change sites by file and function), TASK/V61.md step 2.
Before code: the spec files under `docs/api/vdi/` that this slice changes are extended for the 32-plane
setting (spec gate, researcher), since no EmuTOS path exists above 16 planes.

Depends on: V62.

## Acceptance

- At 32 planes fills, lines and text draw with the pen's pixel; a cleared screen reads back as the white pen through
  every read path; logic operations are bitwise on 32 bits.
- At 16 planes nothing changes (same bar as V62).
- `cargo xtask test` green; both board builds; warnings delta 0; doc-check of the edited docs 0 failures.

## Spec gate (researcher, 2026-11-18) and the lead's reading of its open points

Spec: `docs/api/vdi/raster/_raster.md` (section "32-plane setting: the device pixel", rules R1-R6, the site
table and the boundary table), `docs/api/vdi/workstation/03-v_clrwk.md`,
`docs/api/vdi/inquiry/_color-pixel-input.md`, `docs/api/vdi/output/_fill.md`. By the site table most rules are
met by the existing code at 32 planes; the one code change is the read mask under `pixelread`; the rest of the
slice is tests that pin the rules at 32 and the unchanged behaviour at 16.

The open points, settled by ADR-038 and the series' cut, no new decision:

1. The flood-fill seed read is masked at 32 planes like every other read: ADR-038 point 4 says "every read
   (`v_get_pixel`, flood fill) masks it off, so a cleared screen reads as the white pen". At 16 planes the seed
   stays unmasked as EmuTOS reads it.
2. `v_get_pixel`'s answer shape stays as it is in this slice; the widened shape is TASK/V65.md (ADR-038
   point 7). The receipt states what the call answers at 32 planes until then.
3. The cleared pixel: the unchanged path (`0xFFFFFFFF`) stands; tests assert the masked read and the colour,
   never the X byte.
