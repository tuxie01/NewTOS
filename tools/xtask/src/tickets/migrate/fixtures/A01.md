# A01 — wind_get(0, WF_WXYWH): geräteabhängige Geometrie absichern

Status: **ERLEDIGT (2026-09-19)** · Priorität: **P2** · Typ: Geräteunterschied / Test

> Quittung: [A01-STATUS-DONE.MD](A01-STATUS-DONE.MD). Kein Codeeingriff: `init_desk_window`/`wm_init`
> leiten die Desktop-Rechtecke aus dem Backend ab (`window.rs`), wie `gemgraf.c:423-424`/`gemwmlib.c:1291-1294`.
> Neu gesichert durch `tos-api/tests/aes_wind_get_desktop_geometry.rs`: `WF_WXYWH` auf Handle 0 = (0, hbox, W, H−hbox),
> auf 640×480 **und** 1920×1080, mit `gl_hbox` aus `graf_handle` statt einer Konstante; drei Negativfälle
> (falsche Breite, falsche Höhe, falsche Menüleistenhöhe) werden erkannt. Der Pi-Messunterschied (nur
> `int_out[3..4]`) ist damit Geräteunterschied, kein Defekt.


Abhängigkeiten: Keine

## Begrenzter Auftrag

Nur WF_WXYWH auf Handle 0 prüfen. Erwartung aus Gerätemaßen: (0, Menüleistenhöhe, W, H − Menüleistenhöhe). Bestehende Tests zuerst prüfen; nur fehlende Eigenschaft ergänzen. Keine Änderung auf TT-Konstanten.

## Abnahme

Beide Profile 640×480 und 1920×1080 erfüllen die Regel; ein falscher W/H-Wert wird erkannt. Keine zusätzliche Hardwareauflösung implementiert.
